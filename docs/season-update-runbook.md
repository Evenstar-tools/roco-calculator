# 赛季内容更新流程

适用于新精灵、首领形态、技能、特性、平衡性调整、NEW/❗及正式赛季数据接续。2026-10-27 根据 [S4 实际历程与返工](maintenance/s4-update-retrospective-20261027.md)重整；历史资料中的临时假设不自动成为新赛季规则。

调用链：`AGENTS.md → 本文 → 对应数据/素材/机制入口 → 当季交接`。赛季装饰另按 [design.md](../design.md)执行，不在数据任务中重做 UI。

## 0. 先确认入口与授权范围

- 在当前开发分支/工作树核对 Git 状态；保留已有未提交内容。有独立新范围时再隔离，不为接续同一任务反复另开线程或覆盖工作树。
- 记录应用版本、当前正式数据/规则身份、目标赛季、生效时间、来源及本轮涉及的平台；应用版本、数据版本、规则版本分别管理。
- 当前 S5 开发只授权 Web / Windows 本地处理。不得调用会写小程序的旧导入器、同步/构建脚本；提交、推送、部署、打包、上传按用户实际授权处理。
- 不把旧 S3 CSV 构建器、硬编码 23 张的 S4 导入器或默认三端发布命令当作每次更新起手式。先确认来源与执行器可用，再推进候选；不先安装依赖、全量测试或打包。

## 1. 统一来源和字段状态

按一个候选条目维护身份与证据，不再将同一批名单分散重复人工抄写。沿用当前候选 JSON / reviewed evidence，记录以下内容即可，不新增无用表单。

| 维度 | 必须区分 |
| --- | --- |
| 身份 | 家族、具体进化形态、首领、外观原色/异色；名称已核验范围与正式 ID 是否已确定 |
| 基础数据 | 属性、六维、技能参数及学习面逐字段确认；未知是 null/空关系，不用 0、相邻值或基底值补齐 |
| 特性/技能机制 | 仅有名称或正文、规则已核验、核心已实现、界面已接通、已验证范围 |
| 素材 | 原图是否具名、是否高清、原色透明图/纯色剪影/通用占位、对应来源和文件 |
| 变更 | 新增实体、已有实体调整、文案修正、来源冲突；保留 before/after、patch 身份和实际日期 |

来源按当前用户确认的证据口径处理：视频/社区资料用于前瞻，官方资料和已核验数据用于正式候选；不同来源冲突逐字段进入 pending，不能仅按“最新时间”覆盖。

先核身份再核数值，先核关系再做默认配置。只确认家族的画面，不给每个模型推测进化名。用户提供的明确分配与推荐值分开，不能用推荐补成“解析成功”。

## 2. 精灵抠图最短路径

### 源素材选择

1. 已有可信透明原图：直接进入检查与等比导出，跳过重新分割。
2. 只有高清海报：确认具名形态，裁出完整主体，再做原图语义抠图和人工清理。
3. 只有视频：优先选完整、无遮挡、清晰的具名实帧；仅家族名标只能绑定家族代表占位。
4. 身份/轮廓不完整：保留通用占位并记录缺口，不补画肢体，不借旧形态冒充新首领。

### 单张打通后批量

`具名原图 → 完整主体裁切 → 原图分割/alpha → 杂点与边缘清理 → 高清原色透明PNG → 等比长边128px → 显式形态key绑定 → 实际卡片目检`

- 保留原形象、颜色、比例和透明通道，去掉文字、箭头、界面、骑乘/同乘人物与背景。纯色剪影从同一主体 alpha 蒙版派生，不生成式重建轮廓。
- 清理连通区域时逐张确认；光环、尾尖、角和悬浮部件可能是不相连主体，不能统一只留最大块。
- 高清透明原稿和运行时图分开保存。运行时按最长边 128px 等比缩放，不将任意矩形强拉为 128×128；需要正方画布时只加透明留白。S4 使用 Lanczos3。
- 核验真实透明像素、四边裁切、残留文字/白边、原色异色混淆、尺寸与文件体积；RGBA 格式本身不证明背景真的透明。
- 不新增交付用 SHA/逐文件校验清单；已有产品协议内部完整性字段保留。素材记录保留来源、形态、处理方法、高清/运行时路径及尺寸即可。
- 在浅/深底和真实头像尺寸读图，确认轮廓及必要部件可辨、没有被 object-fit/画布留白压得过小。

### 已有入口和缺口

- S4 成品：`C:/Users/Administrator/Desktop/s4新精灵/高清版_抠图处理/`。README、资源清单及清理记录证明历史流程和规格；本轮尚未找回实际语义分割脚本/模型，不能宣称一键重跑。
- `scripts/bwiki/import-s4-preview-portraits.mjs` 仅导入已抠 PNG，固定 S4 数量/命名且默认写小程序。新季不直接运行。
- S5 Web 资源绑定已有 `src/features/s5-preview/catalog.js` 的 `entry.asset`。先补齐原图分割执行器的一张成功样例，再批量输出及绑定；执行器入口与真实命令应写入当季交接。
- 当前 S5 imagegen 参考轮廓待原图抠图替换，不计入上述素材验收完成。

## 3. 新家族、技能与首领先占位

- 每个已核验的具体形态有独立稳定本地 ID；未知进化阶段不虚构。未拿到正式身份时保留 candidate key 和后续映射入口。
- 未知六维用 `raceStats:null`，未知学习面为空，未知技能参数保持 null；不得补默认性格/个体/四技能来制造可计算状态。
- 首领独立身份、特性及素材绑定，不能无证据复制普通形态的六维、属性、学习面或图鉴号。S4 曾采用复制基底的特定决策，不自动套用 S5。
- 能确认进化关系时同时补正反向索引；至少验证从普通形态搜首领、从首领回普通形态、切换后配置归属，防止重演 1.6.11 的单向链漏项。
- 复用原精灵列表、卡片与特性说明；占位仅给相关的短缺项提示，不把日期、来源审核或内部实现细节堆进主界面。
- 占位可搜索、选择和保存引用；计算与六维编辑不得绕过未知资格。正式资料优先，前瞻层不能覆盖正式实体。

当前 S5 展示入口：`data/candidates/s5-preview-new-spirits.json` → `src/features/s5-preview/catalog.js` / `with-web-preview.js` → 原 `App` / `SpiritPicker`。它没有直接写入正式快照；国际服数据边界不因中文前瞻而改变。

## 4. 特殊机制一次打通真实链路

每条机制先明确：触发事件和时点、读取哪方、状态归属、基础/实际能耗、当前/累计量、作用乘区、上限、持续/离场/重置、一次性与组合顺序。没有证据的项保持待核。

按现有路径实施最小纵向功能：

`规则证据 → 状态保存/生命周期 → 原有参数控件 → 有效特性合并/实例投影 → 面板与伤害求值 → 来源摘要 → 原界面回归`

- 简单百分比和条件优先复用 `trait-effects.js`；状态转换、连锁、按次和攻击后结算进入已有对应求值路径，不将所有效果塞进通用攻击百分比。
- 状态按精灵、方向和特性实例隔离；交换攻防、切换精灵/技能、撤回、刷新、队伍和分享按真实需求接续。派生值从状态求值，不在渲染里累加，不重复计伤害。
- 复合机制先汇总事件再按明确顺序求值；S4“灵魂灼伤＋加个雪球”曾出现加入顺序影响结果，应保留顺序无关回归。
- 同时检查攻击区/威力区/最终倍率、固定值/百分比。S4 旧玩具、得寸进尺证明单一对局相等不足以验证作用区。
- 最小回归覆盖未触发、触发、边界阈值、上限/一次性、切换/重置及一个关键组合；依据用户实际故障补例，不默认穷举所有组合。
- 最终面板、逐技能结果、主结果/手机底栏必须读同一求值状态；累计增益区分“潜在可得”与“实际已生效”。

**数据完整和机制可算分别放行。** 未实现/未核验的机制不能因填齐种族值自动以“无特性”计算。运行时必须保留可执行的支持状态，不能只依赖会被裁剪的 provenance，也不能只加“仅展示”文字。

现存需补的门禁：核心仍有描述推断 fallback，当前还没有一条已验证的通用新季机制守门链。本轮将其列为 S5 正式计算放行前的待实现/待验证项，不将静态风险说成已有线上错误。

S5 当前 `mechanics.js` 是隔离预开发合同，全部 `calculationEnabled:false`，未接入正式引擎。冥古龙/阿布还涉及固定 60 级核心的适配；正式特性名、能耗口径、冻结阈值、骰子映射等核验后才能逐项接入。不能只导入六维便宣称完成。

## 5. 正式资料导入：保留身份，替换已过期关系

1. 先冻结最后一份完整旧季数据、规则身份、对应规则实现提交/版本、活动改动台账与资源绑定，明确旧规则回放兼容范围；不改历史快照。仅存规则版本字符串，不能证明当前引擎可重放旧季硬编码机制。本次 S5 的 before 必须是当前 S4，不能拿已有 S3 快照代替。
2. 读取新 BWIKI 的 Catalog、Skills、Learnsets、Evolutions、Config、Index 六模块；资料缺失/限流先停止该输入链，不扩大外围实现。
3. 建立经审核的 season profile：版本、赛季、日期、来源模块修订和实际审阅后的数量。不能只改预期数量让校验变绿。
4. 先只读检查，再写独立候选并审差异。下面是已有入口；profile 路径仅为示例，文件经审核后才可运行：

   ```powershell
   node scripts/bwiki/nrc-source.mjs
   node scripts/bwiki/apply-nrc-current.mjs --profile data/reviewed/nrc-s5-import-profile.json --import --check
   node scripts/bwiki/apply-nrc-current.mjs --profile data/reviewed/nrc-s5-import-profile.json --import --output output/nrc-audit/s5-candidate.json
   npm run -s data:season-diff -- --before data/snapshots/current.json --after output/nrc-audit/s5-candidate.json --output output/nrc-audit/s5-diff.json
   ```

5. 逐项审精灵身份/属性/六维、技能威力/能耗/类别/描述、特性同名规则变化、进化链、学习途径、头像与缺失项。当前学习面按正式来源替换，不能并入过期 S3/S4 关系。
6. 保留已有 ID；正式更名优先改名不换 ID。误绑定已有其他实体时迁移引用并保留历史兼容；学习面撤销后只移除非法默认槽，不擅自挑替代技能。
7. 前瞻→正式映射必须恰好一对一且可审核。同名不同形态、首领、上下弦等不可模糊匹配。验证旧收藏/队伍/分享；输出 ID 映射表不等于已接通状态迁移。
8. 正式资料优先后，旧前瞻/公告/截图覆盖器不得重新盖回旧值；审旧入口重放及重复导入幂等。
9. 只有本次要用的数值/机制/关系通过资格门禁，才切为可计算；资料完整但机制未做的条目继续阻断相应计算。

现有 `apply-nrc-current` 默认仍是 S4 profile；它的 `output/nrc-audit/before/current.json` 备份路径存在即保留，不能当成每个赛季自动归档。正式切季前必须单独确认新的旧季基线已留存。

旧 `ROCOM_S3_CSV` / `ROCOM_BWIKI_CACHE` 与 `data:build` 路径只用于历史重建，要求对应本地 CSV/缓存和正确赛季参数；新 NRC 已有权威数据时不回退到旧 S3 常量构建。

## 6. NEW / ❗与新版轮换

### 展示优先级

下表为目标规则。现行已实现“非 new 改动优先于 NEW”；非活动记录隐藏仍依赖后续周期闭环。

| 实体状态 | 展示 |
| --- | --- |
| 有非 new 的改动明细，包括数值、规则、学习关系或文案 | ❗，打开真实 before/after 和该条 patch 日期 |
| 本期新增身份，且无上述改动项 | NEW，遵守已有形态资格和排序规则 |
| 非活动新增/调整 | 无标记；历史证据仍保留 |

NEW 不应吞掉调整详情。新增首领是独立新增身份，不把其普通形态一并标成 NEW。仅换显示主题、语言、应用补丁包不制造游戏内容新增标记。

### 建议的周期约定（本轮整理流程，尚未自动实现）

- **NEW**归当前正式赛季新增身份；**❗**展示当前正式赛季内仍保留的调整台账，按实体保留原补丁日期。沿用 S4 同季修补不批量改旧日期的做法。
- 普通应用版本修复不清空游戏赛季标记；预览 S5 装饰不切换正式 S4 标记。
- 正式切到 S5 时，先归档 S4 台账，再让旧 NEW/❗退出活动展示，从审核过的 S5 新增与差异重建。不能仅替换顶层标题让旧内容冒充本次调整。
- 同一赛季的新平衡补丁，只更新真实受影响实体；未变化实体不换日期。有新旧并存时优先❗，同时保留新增身份资料。
- 若后续明确改为“仅最近一次补丁显示❗”，需单独调整活动 patch 范围与测试，不依靠普通打包顺便清理。

现行 UI 只读 `isNew/items`，没有赛季自动失效。当前工作树已有跨数据版本清理活动记录的准备，但历史归档、新差异重建和 UI 周期约束尚未形成闭环。应补回归：旧季退出、新季新增/调整进入、混合身份优先❗、同季不改无关日期、预览主题不切周期。

## 7. 验证与交付按受影响范围执行

| 改动 | 最小充分验证 |
| --- | --- |
| 抠图/头像绑定 | 原图对应关系、实际透明/比例/边缘、浅深底与真实卡片、离线资源可加载 |
| 候选录入 | 唯一身份、引用/进化链、未知数值/技能阻断、正式优先、幂等、原数据未被覆盖 |
| 正式导入 | 候选差异、同名规则、身份保留/迁移、学习面和合法默认槽、历史快照不变 |
| 特殊机制 | 关键失败用例及边界、同一状态下的真实面板/伤害/来源、切换与恢复 |
| NEW/❗ | 原卡片、候选列表和涉及的技能入口；周期、优先级、日期、交互不误选 |
| Web / Windows | 相关定向测试、必要构建；真实网页和实际 Electron 离线协议验证，浏览器页面不代替桌面 |

文档流程修改读回文件与链接即可；不为文档变更全量测试或构建。实现达到通过条件后停止重复验证；有新改动/失败才补相关验证。发布时再执行 [发布检查单](maintenance/release-checklist.md)的适用平台门禁；当前小程序不在授权范围，不能复制整组同步命令。

当季交接分别写清：证据和候选、数据入库、机制支持、界面实测、未决规则、提交/推送/部署状态。保持当前授权边界，不用本地构建代替线上、上传或正式发布结果。

## 8. 当前 S5 执行顺序

1. 先补精确原图分割执行器的一张成功样例，按 S4 规格重做现有生成轮廓；可直接取得透明原图的条目优先导出。

3. 在可计算放行前补执行资格守门、真实 S4 before 归档和 NEW/❗轮换闭环。
4. 官方数据到位后走 reviewed profile→候选差异→审核身份/学习面/同名规则→逐条真实机制接线；再验旧配置引用和同条件新旧伤害。
5. 按用户届时授权处理提交或发布。本轮仅优化流程，没有替换素材或修改运行时。
