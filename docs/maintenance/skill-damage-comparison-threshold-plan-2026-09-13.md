# 承伤对比：击倒线需求与 UX 评估

2026-09-13｜核对当前本地 Web 2.0.2 源码、实际界面与既有领域测试。最小收敛版已在本地实施；旧扩展方案继续搁置，未发布。

## 当前有效方案：最小收敛版

根据用户“把改进做最小程度收敛”的要求，以本节替代后面的扩展方案；原审计证据保留，三张旧示意图不作为本次实施范围。用户确认示意后已实施本节三项；最终验证和未完成的发布门禁见 `skill-damage-comparison.md` 末节。

目标只保留一句：**设定一招和条件，查看全榜哪些精灵能被击倒。** 不做自动找最优解，也不完整复刻Excel。

入口、显示设置开关、现有弹窗和结果列都不动，只保留三项改进：

1. **记住选择，沿用筛选。** 同一攻击来源关闭重开时保留技能、耐久模板和筛选；读取主界面最新条件重新计算，不缓存旧伤害。来源变化时重新校验技能选择。“达到100%／低于100%”直接改称“可击倒／未击倒”，保留原判定逻辑和不计防守特性的说明。
2. **复用已设置的星陨／冻结。** 只在既有筛选区加一个默认关闭的“沿用星陨／冻结”勾选项；选中后，把当前目标的这两项状态统一应用于候选目标，并在现有口径说明中显示数值。己方层数、天气及目标层数仍在主界面设置，不在榜内复制条件编辑器。只允许明确的状态字段，不复制旧目标血量、种族值、特性或其他异常；仍只计算本次直接伤害。
3. **复用防守配点。** 在原耐久模板下拉中增加“当前防守方配点”，将当前防守方的性格和个体配置用于各候选精灵；候选仍使用各自种族值、属性和统一等级。原模板不改，不新增模板管理；详情显示实际使用的配点，不能继续固定写“生命／双防各60”。研究三种配置时先手动调整主界面配点，再回榜查看。

用户动线：主界面选攻防、技能并设条件 → 打开承伤对比 → 按需勾选沿用星陨／冻结、选择当前防守方配点 → 筛“可击倒” → 点目标复算。尝试其他层数时关闭回主界面修改，再打开即可沿用选择。

**本次不做：** 新模式、侧栏、判定方式下拉、榜内条件编辑器、移入口或解除防守方前置、三套配置并排、最低能耗技能、最低层数反查、两回合连招、批量防守特性。前三张大幅调整布局的思路均搁置，不要求用户继续三选一。

最小验收：关闭重开保留选择但伤害按新条件更新；勾选状态开关前后按实际规则计算，关闭仍保持原标准榜口径；自定义配点与单只无防守特性复算一致；未知条件仍不纳入，不能归入未击倒；明确代入才修改主配置，并沿用既有可撤回行为。新增状态和配点须与代入参数一并保持一致。窄屏只增加一个短勾选项和一个下拉选项，不新增结果列，不产生横向滚动。

方案采用 Design Craft 的最小改动原则，优先复用现有控件，不把每个计算需求都转成新模式或新面板。下图为此前用于确认的 ImageGen 示意，不是实拍；实施后的真实页面保存在 `output/playwright/dc-minimal-*`。本次未开展新一轮全面 UI 审计，实施保持先小程序、后 Web／桌面的顺序。

## 原版审计结论（现状证据）

现版能完成“固定一招，列出全精灵的承伤和击倒名单”，不能完整替代需求截图中的三套耐久、最低能耗技能和两回合击倒表。计算核心和列表可以复用，缺口主要在统一场景、模板定义、批量搜索策略与条件编辑动线。

特别注意：能够设置某个条件，不代表该条件会进入当前承伤榜。现版主动清理原防守方的星陨、异常和能力变化，避免把旧目标污染到所有候选；这对标准承伤榜合理，但不满足统一指定星陨层数的击倒线查询。

## 需求拆分与现状

| 需求人要的效果 | 现版结论 | 依据和限制 |
| --- | --- | --- |
| 固定技能，看哪些精灵会被击倒 | 能 | “达到100%”筛出本次直接伤害达到满血生命的目标；不计防守特性 |
| 设置己方特性层数、天气后批量计算 | 部分能 | 保留已适配的己方技能／特性条件、天气；榜内不能直接改，只能返回主计算器再打开 |
| 给所有目标统一设置星陨、冻结等层数 | 不能按现版直接做 | 目标印记、异常和目标条件会被清理；不能宣称支持截图里的所有层数场景 |
| 比较截图中三种耐久配置 | 不能等同 | 现有四种模板只换性格，个体都固定生命／物防／魔防各60；不是“仅生命个体”等三档 |
| 自动给每只精灵找最低能耗击倒技能 | 不能 | 目前只能逐次切当前携带技能看独立榜，没有逐目标择优结果 |
| 自动反查最少几层能击倒 | 不能 | 可以人工改受支持的自身层数后重开榜；没有最低层数搜索 |
| 折射／冻结加另一招的两回合击倒 | 不能自动批量做 | 本榜关闭回合末异常结算，也没有逐回合状态推进；主计算器已有的部分本／下回合异常显示不等于通用连招引擎 |
| 对计入防御特性的实际目标再核实 | 能单只复算 | 显式代入后恢复原生特性，因此结果可能改变；批量榜仍不计防守特性 |

## 当前用户动线与实拍

### 1. 开启功能：可用，首次路径较深

菜单 → 显示设置 → 开启承伤对比。默认关闭、保存选择符合用户此前要求，继续保留，不增加首页常驻模块。

![显示设置](D:/codex/rock-calculator-public/output/ux-incoming-damage/threshold-audit/01-setting.png)

### 2. 准备来源：可用，但有无关前置条件

选择攻击方、技能及需要的己方条件；现有入口依赖完整攻防配置，所以即使要比较“所有目标”，也要先选一个防守方，才能出现技能区和结果入口。当前实拍视口下入口在底部，宽屏使用结果栏入口。

建议启用开关后，将打开入口放到攻击方技能标题旁；仅选攻击方与技能也能进入，不必先随便选择防守方。不同时堆放多个重复入口。

![结果入口](D:/codex/rock-calculator-public/output/ux-incoming-damage/threshold-audit/02-entry.png)

### 3. 查询击倒名单：能完成单招目标

打开承伤对比 → 选技能、耐久模板 → 点击“达到100%”。本次实拍在页面当时配置下选择“灼伤”，出现6只目标；这是该演示配置的结果，不是通用配招结论。

正向找击倒目标时，“可击倒／未击倒”比“达到100%／低于100%”更直接。排名保留全榜名次是既有规则，筛后从314开始容易被误认成结果条数；新击倒方案模式可以直接不显示名次。

![单招击倒筛选](D:/codex/rock-calculator-public/output/ux-incoming-damage/threshold-audit/03-ko-filter.png)

### 4. 展开和复算：动作明确；连续试条件不方便

点行展开不会改主配置，“代入防守方复算”是明确的主动作，应保留。界面会说明恢复防守特性，避免把无特性榜当成实际必杀结论。

本轮实测：切到灼伤、魔防性格并保留“达到100%”，关闭再打开后回到种子弹、生命性格和“全部”。连续尝试几层、几种耐久，需要重复找技能和筛选，成本偏高。

## 原扩展方案：增加击倒方案（已搁置，不在本次范围）

### 整体动线

首次在显示设置开启 → 选择攻击方和技能 → 打开承伤对比 → 选择单招承伤或击倒方案 → 设置统一条件和耐久配置 → 查看可击倒／未击倒／待复核 → 点目标展开 → 需要时显式代入复算。

单招承伤回答“这招打谁多少”；击倒方案回答“当前候选技能里，用哪招最省能量能击倒”。不要混成一个只有百分比、却说不清判定范围的排行。

### 只补三个界面能力

1. **同一窗口切换模式。** 保留原单招承伤，不新增主页大模块、独立入口菜单或一张横向长表。当前四技能上下文继续复用。
2. **统一条件就地修改。** 技能／特性相关层数、目标星陨、天气只展示与当前场景有关的项；常用层数直接修改，更多条件折叠。分清己方特性层数与目标印记层数，不使用含义不明的统一“层数”框。改动只作用于对比草稿，不偷偷修改主计算器。
3. **结论优先、详情折叠。** 列表首屏只保留精灵、命中技能、实际能耗、判定结果；伤害值、配点、候选技能和公式放在展开行。无可用技能显示“未击倒”和横线；条件缺失显示“待复核”，不能当成未击倒。

### 计算口径

- 截图的“最低即可击杀的技能”没有明确是最低威力还是最低耗能。本方案暂按最低实际能耗理解；若原表按威力排序，应明确改用该口径，不把两者混称为“最低”。这是方案假设，不是已核准的原表规则。
- 最低能耗首先限定为**当前四招中的最低实际能耗**，计入当前条件已适配的减耗。不能称为全技能最优，也不把之前为叠层花费的能量算成免费连招总耗能。
- 同费有多个可击倒技能时，优先展示过量伤害较小的一招，并在详情列出其他同费候选；技能编号用于稳定排序。
- 将目标的统一星陨／冻结等显式写入独立“本次场景”，逐只构造防守方后再应用。不要简单取消旧目标清理逻辑，否则原防守方的残血、特性开关等会污染全榜。
- 三套耐久配置要保存完整性格、生命个体、物防个体、魔防个体，名称只是摘要。截图能辨认“仅生命个体”和“双生命魔抗”，但第三套和全部准确配点需要原表核实。示意图的“魔耐配置”是拟议名称，不等于已经还原原Excel。
- 继续默认不计防守特性；列表明确标注口径。若未来提供批量计入特性，需要逐只识别条件依赖，无法确定的标为待复核，不能一律假定触发或不触发。
- 反查最低层数时，只选择一个有定义和合法范围的变量逐档计算，返回范围内首次可击倒层数；不能把不同特性都按统一上限，不能未经验证假定伤害必然单调。

### 保持简洁的具体限制

- 一次显示一个耐久模板，不把三套结果同时铺成Excel宽表；切模板保留搜索、筛选和当前目标。
- 不叠加第二层弹窗；配置使用行内展开，手机同样是单列主列表。
- 当前来源摘要始终可见，显示哪些场景条件生效；修改条件后旧结果不能继续冒充新结果。新计算可以取消旧请求。
- 回到主计算器再打开，保留对比的筛选和浏览位置；攻击来源改变时更新摘要并重新计算，不复用错误的旧结果。
- 单招模式显示承伤百分比；最低能耗模式显示命中技能和能耗；最低层数模式显示临界层数。按模式替换列，不累计新增列。
- 只有一个判定策略时不显示空泛的策略下拉；最低层数策略实际交付后再开放对应选项。

## 原扩展交付顺序与验收（已搁置）

### 先交付：固定场景的单招判定和最低能耗技能

优先修入口前置条件、显式统一目标状态、完整耐久模板与榜内条件编辑，再接当前四招的逐目标能耗选择。这样能先解决需求人“给个层数和技能，看哪些精灵能杀”的主诉。

验收必须包括：星陨0层和非0层进入核心后确实不同；旧目标个人配置没有泄漏；模板切换使用正确个体和性格；最低能耗在候选范围内正确；同费、0能耗、无直接伤害、数据缺失和未知条件明确区分；关闭不改主配置；代入才修改且可撤回。

### 再交付：最低层数查询与两回合方案

最低层数可以复用统一场景与逐档计算。两回合另设方案编辑：第一招 → 回合间结算 → 第二招；按核心实际支持推进生命、冻结／星陨等状态、增减益、触发条件和能耗，不能做“伤害×2”或独立两次伤害相加。

两回合首期应限定为用户指定的序列和已支持机制，明确不模拟对手行动、回血或换人，除非用户显式设置。未支持的状态转移提示待复核，不输出确定击倒结论。完整替代截图表格前，还需要核准折射／冻结与非极寒等列的精确条件。
