# “铭记于月亮”前瞻实现与正式版复核单

状态：2026-09-02 已完成 Web、CLI 与微信小程序的第一阶段本地前瞻实现，尚未打包或发布。本批只交付“搜索/多选 + 已适配特性计算”，吞噬特性数量上限为 5；攻击后失去 5% 生命的自损暂不实现。特性原文来自用户提供的 S4 整理资料，正式细则仍须在 2026-09-10 与正式资料、BWIKI 和实测二次核实。

## 已实现范围

“铭记于月亮”当前原文为：获得自己击败的精灵的特性，每次攻击后自己失去 5% 生命。

- 只有原生持有“铭记于月亮”的精灵可以配置已吞噬特性；不能通过普通特性输入或分享字段给其他精灵伪造该能力。
- 银月狼王的原生特性始终保留，已吞噬特性以附加列表合并，不覆盖原生特性。
- 支持按精灵名、图鉴号、拼音、首字母或特性名搜索；一个精灵有多个特性时逐项选择，不会一次全部加入。
- 支持加入最多 5 个特性、稳定去重和逐项删除；达到 5 个后不能继续加入，删除后恢复可选。同一个特性被多个精灵持有时，候选按特性 ID 去重；当前不记录被击败精灵的来源实体。
- 已选特性显示“已适配/仅展示”。仅有真实规则适配的特性参与计算，不从描述文本临时猜数值。
- 需要条件或数值的已吞噬特性按 `traitId` 独立保存参数；相同控件名不会在多个特性之间串值。
- 攻击、减伤、速度、连击、技能威力、技能变形、负面状态、直接特性伤害及已明确适配的特殊特性统一读取有效特性列表。
- 第一版由用户手动维护已吞噬列表，不自动监听击败事件；列表数量上限为 5。

## 状态与分享

战斗方会话字段为：

```text
acquiredTraitIds: string[]
acquiredTraitValues: Record<traitId, Record<canonicalInputId, scalar>>
```

- 切换精灵、载入个人配置或队伍预设时清空本场已吞噬特性，避免串到另一只精灵。
- Web 会话支持撤销和完整分享链接往返；个人常用配置不保存本场吞噬状态。
- 小程序本地战斗状态支持恢复与撤销；旧版持久化数据和旧分享默认补为空列表。
- Web、CLI、小程序持久化和分享边界统一执行最多 5 个的限制，异常输入不能让第 6 个特性参与计算。
- 小程序分享受 899 字符上限约束，会优先降级为 `reduced` 或 `minimal`。界面会在发送前和接收页明确提示“吞噬特性/参数可能未完整携带”，不会把降级分享标成完整。

## 本批暂不实现

“每次攻击后自己失去 5% 生命”只保留在前瞻特性原文中，本批不进入计算：

- 不生成“铭记于月亮”自损公式或特性结算项。
- 不改动攻击方当前生命，也不显示自损提示。
- 多段攻击、选择技能额外执行和反击均不触发该自损。

自损触发时机、计算基数、取整、结算顺序和力竭边界留到 2026-09-10 正式资料验收后再开发，不在前瞻阶段猜测临时口径。

## 已验证行为

- 可按精灵或特性连续加入最多 5 个特性；达到上限时第 6 个不可加入，删除一项后恢复可选；重复加入无副作用。
- 原生“铭记于月亮”不会被吞噬列表覆盖或删除。
- 已吞噬特性的条件值彼此隔离，并可通过会话、撤销和分享结构读回。
- 普通精灵不能借助注入字段、未知 ID 或孤立参数启用吞噬特性。
- 已吞噬的威力、攻防、速度、连击、选择技能、展翅、负面状态、直接伤害、稀兽花宝、契约的形状、戏耍和贪得无厌等已适配路径均进入原有计算逻辑。
- 同一威力百分比乘区继续加算，例如旧玩具与冷光源按各自规则共同进入加算区。
- 伤害技能、多段攻击与选择技能额外执行均不产生“铭记于月亮”自损。
- Web、CLI 和小程序使用相同的安全字段、特性 ID 与 canonical 参数约束。

## 2026-09-10 必须复核

1. “失去 5% 生命”按最大生命还是当前生命计算。
2. 取整方式，以及能否令自身力竭。
3. 与吸血、回复、技能自损、反伤及其他攻击后效果的先后顺序。
4. 被击败精灵有多个特性时，是全部获得、选择一个，还是按实际生效特性处理。
5. 正式资料中的吞噬数量上限是否同为 5；重复击败同一精灵是否有额外效果。
6. 换下、返场、进化、复制、清除或战斗结束时，已吞噬特性是否保留。
7. 是否需要持久记录每个已吞噬特性的来源精灵；当前只保存规范化特性 ID。
8. 特性冲突时的优先级，例如多个改形态、固定连击、选择技能或直接伤害特性同时存在。

任何一项与正式资料不符时，先补失败用例，再修改规则和两端镜像；攻击后自损必须等正式口径确认后再开发，完成 BWIKI 二次验收前不得把前瞻范围标为正式口径。
