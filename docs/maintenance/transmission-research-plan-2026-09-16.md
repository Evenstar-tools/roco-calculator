# 传动计算器：公开产品调研与完善计划

调研日期：2026-09-16。交付为计划和界面示意，本轮不修改功能代码、不发布。本文补充上一版 transmission-calculator-2026-09-16.md；原文测试结果属于原实现，不作为本计划已实现的证明。

## 判断

目标应从“四槽顺序记录器”提升为“能解释每回合位置、判断当前可用技能、比较选择分支的推演工具”。先补规则与可用性，再补视觉；轮班完整支持是验收项，不能用手动排列入口替代。

公开检索中，本轮确认并实际操作了一个直接同类产品 Roco Showdown。另核查 lovepvp.top、洛克工具箱、RocoDex 三个相邻产品。没有证据说明这是市场全部产品，也不把旧域名、同站教程和集成入口算成独立竞品。

## 当前方案需要纠正的问题

1. **配置脱节**：载入攻击方只带四技能，特性另选且默认清空；还缺精灵身份、可学习限制和临时技能的明确区分。改为复制一份完整推演快照，显示继承来源；实验配置允许越过学习面但要标记。
2. **位置不等于能出招**：正位宝剑只允许1号位，宝剑王牌允许1/3号位。当前通用下拉没有这两种限制，必须纳入行动可用性。
3. **遗漏位置关联收益**：齿轮扭矩、联动装置、能量守恒不直接产生传动，却依赖位置变化或两侧技能。上一版关键词筛选未覆盖这些反向描述。现有23技能/15特性清单至少增补这3技能、2特性；按作用分类注册，不能只靠正则推定完整性。
4. **时间轴不足**：目前只有开始/行动两段，缺入场、回合内分支、回合结束与下一回合的可视区分。UI展示阶段不代表擅自确认它们内部的游戏结算优先级。
5. **未知规则的代价过大**：身份变化要求重新配置会清空历史。改为在该事件位置暂停，记录观察到的技能身份或顺序，再续算；前序证据保留，下游标记依赖实战输入。
6. **明暗尚未完成**：power/drive只是工程键，现有选择序列只能说明本项目如何安排两种效果，不能证明明暗标签、额外传动时机或重复基础传动。
7. **日志可读性不足**：长文本不能直观看出哪张技能牌去了哪里。主视图应呈现四槽、身份标识、层数及变化路径；明细按需展开。

## 完整范围与优先级

### P0：规则证据与测试基准

每条规则登记实体ID、数据版本、触发阶段、目标、方向、层数、重复条件、上限、固定槽冲突、依据和可信状态。可信状态区分：游戏文本确认、社区实现对照、实机验证、尚未确认；实现支持程度另列，避免“有描述=已实现”。

优先补轮班的证据：无选择特性、有求必应、一意孤行 × 两种效果 × 初始1/4号位 × 是否叠加位置特性/固定技能。记录每次入场、回合开始、行动前后及下回合的完整四槽；记录视频时间戳与版本。先确认明暗映射，再给按钮标注明/暗；确认之前仍显示效果名称。竞品结果可作为差分样本，不能单独升级为游戏事实。

### P1：可用的回合规划界面

- 入口仍在现有菜单；保持弹层和手机适配，不重做伤害计算主页。
- 从当前一侧配置或已有精灵配置载入，自动继承相关特性；查看/替换技能复用现有选择器。
- 初始四槽支持拖动交换，同时提供点击选中后交换，保证手机、键盘与读屏可用。
- 中央四槽以技能身份为追踪对象，显示“当前槽位、剩余层数、固定、冷却、不可用”。颜色只辅助识别，不能替代名称与文字状态。
- 开始回合自动预览；“下一层”解释过程，“结算到可行动”到达操作节点。阶段前进不重复执行已结算事件。
- 行动选择中直接禁用位置不合法或冷却技能；位置受限原因就地显示。
- 提供上一步、回到初始、历史回合跳转。从旧回合更改行动时新建分支，保留原分支用于比较。
- 手机四槽2×2，回合记录按行收起；主要操作保持可达，320/390宽度不横向滚动。
- 计划示意中的交互只展示已确认的基础排列；轮班未知分支不填虚构终态。

### P2：补齐选择、随机与位置收益

- 轮班以两个效果并列呈现；特性追加序列单独列出。规则确认后同步给出最终槽位、可用性和下一回合影响。
- 机械变式、风速仪、齿轮扭矩建立事件观察与累计状态。必须分清逐次移动、回合净变化、传动层数和被动让位，不能直接拿数组下标差计收益。
- 联动装置、能量守恒及轴承/减压阀的相邻效果按技能身份保存，位置移动后重新确定邻居。伤害及显示威力复用既有引擎；确定性模拟步骤不直接写回主计算器。
- 盲拧在确认与传动的先后后，优先提供所有可能排列及去重；概率分布未确认时只称“可能结果”，不默认均匀概率。任意抽样必须明确标为样本。
- 观察录入支持点选四槽重排或替换实际技能，不要求用户心算“2413”。未知原因记录在具体事件，下游保留来源。

### P3：全队与技能身份变化

- 过山车扩展到己方6×4槽位；队伍人数、空槽、首尾回环、固定技能交互需要专门确认。按队伍展开，而不是把更多技能塞进现有四槽面板。
- 隐藏条款增加必要的对方四槽；借用/取念/复写保存随机后技能实例；镜像反射、翻垃圾桶补入场或应对上下文。
- 裁决/滋养/点燃/净化以及夺目处理替换或新增技能，不把身份变化错误表示为排列变化。
- 以上是原“所有特性和技能”目标的剩余范围，不能因分期而宣称已经完整支持。无需扩展成完整PVP战斗引擎；只收集这些机制需要的输入。

## 最小实现结构

- 保留现有纯位置结算函数和SkillPicker；状态从组件零散字段整理为推演会话，包含规则版本、初始配置、技能实例、回合阶段、行动与分支。
- 技能实例用稳定instanceId跟踪，附着使用次数、累计收益、冷却和被替换来源；槽位只保存当前排列，禁止使用数组下标充当永久身份。
- 每条事件保存before/after、来源、规则ID、确定性与外部观察。纯函数返回事件和下一个状态，渲染只消费结果。
- 未确认规则只暂停依赖它的分支；可以回退、看前序或比较其他已确定分支，不能自动跳过并输出“成功”。
- 增加显式规则覆盖注册表和数据漂移检查。新数据出现传动/位置/顺序/两侧/替换相关文本但未登记时，测试报告缺口；不把正则直接当行为实现。

## 验收矩阵

| 维度 | 验收信号 |
|---|---|
| 基础排列 | 16种单层、混合层数、4→1、全0、全传动、连续10回合；与固定输入输出逐项一致 |
| 固定技能 | 主轴、锁芯、多个固定槽与交换冲突；逐项标注证据，不靠类推宣称实机验证 |
| 可用位置 | 正位宝剑1号；宝剑王牌1/3号；传动后可用槽变化；冷却随技能实例移动 |
| 选择交互 | 轮班两个分支及两种选择特性；时机、追加次数、基础/额外层数、上限有独立实机样本 |
| 位置收益 | 齿轮扭矩、机械变式、风速仪；移动后回原位与被挤动的反例；相邻技能变化后读值正确 |
| 随机/观察 | 可行排列去重，未确认概率不显示百分比；观察修改保留此前历史与来源 |
| 身份/全队 | 过山车、交换/偷取/替换、空槽；技能实例属性不串到其他技能 |
| 操作恢复 | 上一步/下一步互逆；同输入重放一致；分支互不污染；新配置清旧状态但可恢复已保存方案 |
| 网页验收 | 单元、界面集成、真实浏览器；320/390手机和桌面；键盘操作；无横向溢出；显示威力及旧选择机制不回归 |

## 实施次序

先完成P0覆盖表和轮班证据任务，同时按已确认基础规则实现P1；P2逐项解除受影响分支的阻断；P3达到全队/身份变化要求后才讨论“全机制”。每项都有未确认、已实现、已实机验证三个独立状态，不能用通过大量现有测试替代缺少的规则验收。

本轮只新增这份计划与示意，不改运行中的传动功能。若继续开发，以本计划和原始目标共同验收，原来的“基础版完成”不等于轮班需求完成。
