# 梦想三三萌化与同族形态切换：实施计划

日期：2026-09-19。基线：`e3393f5`，Web 2.2.1 / 小程序 1.1.19。本轮只调研和制定计划，不修改产品代码、不提交发布。

## 结论

将“本场同族切形态”和“重新载入一只精灵”拆成两个明确动作。同族切形态默认保留本侧已调配置和战斗状态，不重置另一侧；新形态重新计算基础面板。先完整覆盖逗逗、气球猫、梦想三三、奇梦咪这条明确的进化链。

按用户补充，三三的鼓气与三鼓作气只按相同数值处理，直接继承层数，不区分永久与非永久。其他家族的萌化默认沿用变形前的有效特性和参数；不因低阶形态的原生特性不同而缩水，也不把更换种族值自动解释成获得另一套特性。

交互复用现有搜索下拉：首次搜索选精灵正常载入；再次打开后，同族区选择视为本场形态切换，不要求用户每次勾选“保留配置”。design-craft 用于控制界面增量，沿用现有行样式、头像和主题，不新建大面板。

## 已查证的参考与现状

### RocoPVP

- [战斗计算器](https://rocopvp.tzrain.wiki/battle)在属性对比中提供“萌化/首领化”，弹窗列出同族谱精灵，并明确只影响本次计算，不回写精灵仓库。已打开实际弹窗核对；没有改动浏览器内已有阵容或战斗配置。
- [2026-06-07 更新公告](https://rocopvp.tzrain.wiki/)说明：特性改为按同族谱内本场已到达过的最高形态保留，下降形态不跟着降级特性。属于对其产品做法的核对，不等于已验证游戏中所有萌化特例。
- [梦想三三图鉴](https://rocopvp.tzrain.wiki/compendium/creatures/205)列出逗逗、气球猫、梦想三三、奇梦咪；鼓气描述与本地数据一致。
- 本轮未在参考站逐项改参数并验证保留结果，因此不能声称其威力、层数、血量等全部细节均已实测。

### 本地根因

- `src/components/SpiritPicker.jsx` 已按 `evolutionChainIds` 展开同族候选，但选择只传精灵 ID，没有区分形态切换意图。
- `src/App.jsx` 的 `changeSpirit` 对所有选择都查该精灵个人配置，然后调用 `selectSpirit`。
- `src/state/calculator-session.js` 的 `selectSpirit → applyConfiguration` 重建 forward/reverse 战斗参数及双方印记；现有测试也明确要求普通换宠清除战斗状态。
- `miniapp/src/components/BattleWorkspace.jsx` 共用这个入口，并额外重置负面状态；小程序再次打开搜索当前不直接展示已选精灵家族。
- 本地已支持鼓气、三鼓作气层数输入，以及撒娇的同侧全技能固定威力累积。缺口不是新增一套加成公式，而是切形态时状态被丢弃，且特性来源与当前形态尚未分离。
- 三三链的同族数组以当前项开头，不能把数组序号当进化阶级；鼓气与三鼓作气虽然是不同数据 ID，但当前攻防公式均为每层 +20%，攻守层数控件 ID 也相同，只应计算一份增益。

## 交互与状态边界

| 操作 | 计划行为 |
| --- | --- |
| 首次搜索并选择 | 沿用个人默认/已有预设载入逻辑；建立本场起始形态 |
| 再次打开选择框 | 优先显示“同族形态 · 保留本场配置”，仍可输入名称搜索其他精灵 |
| 点击同族区另一形态 | 切本场形态，保留配置与战斗状态；不读取目标形态预设覆盖 |
| 点击当前已选形态 | 无操作，不重置、不叠加、不增加撤回记录 |
| 搜索并选择其他家族 | 保持现有普通换宠行为；本轮不顺带重写普通换宠清场政策 |
| 明确载入常用配置/队伍配置 | 仍是配置替换，结束该侧形态覆盖，建立新的起始形态 |
| 撤回 | 一次恢复形态、特性来源、血量和所有保留参数 |

同族关系按真实族谱 ID 校验，不能靠名称相似或搜索结果的 related 标记推断。主计算器入口显式允许形态切换；队伍成员编辑、技能查询、传动及电鹿等其他 SpiritPicker 消费方不被全局改变。

### 保留与重算清单

| 类别 | 保留什么 | 需要更新什么 |
| --- | --- | --- |
| 配置 | 性格、六项个体、已选技能和顺序、单/四技能模式、当前技能位置 | 当前形态名称、原头像、种族值及计算基础面板 |
| 威力 | 固定/百分比加成、撒娇等累计来源、逐槽威力与手动覆盖、已配置技能条件 | 从新基础面板重新计算伤害，不搬旧计算结果 |
| 能力 | 已填攻击/防御能力等级、独立能力修正、速度修正 | 面板与先手提示重新计算 |
| 特性 | 已有触发开关、层数和手动效果值；三三共用原有层数，其他家族沿用原有效特性 | UI、攻守结算统一使用本场有效特性；不把新形态原生特性额外叠上去 |
| 战斗 | 双方印记、异常、天气、场地、减伤、独立乘区与技能进度 | 只重新派生与新形态相关的结果，不改变对方输入状态 |
| 血量 | 保留输入口径：百分比输入保留比例；显式 HP 保留数值并约束到新上限；默认满血仍按新上限 | 最大生命随形态重算。此为计算器输入保留策略，不宣称模拟游戏萌化实际血量变化 |

已有技能不能因为低阶形态学不到就被清掉；这是同一只精灵的本场变形，不是重新组队。手填最终威力/面板等覆盖仍需保留“手动覆盖”标识，避免用户误以为新形态没有参与计算。

## 三三的特性方案

1. 逗逗、气球猫、梦想三三、奇梦咪互切，直接继承已有层数和手动效果值。默认每层双攻、双防 +20%，3 层始终是 +60%，不清零、不重复计算。
2. 不增加“永久”开关，不区分“使用时/使用后”的回合时序，不因这种文案差异增加操作。
3. 特性名称可正常随当前形态显示；底层将这两个特性视为本功能中的数值等价项。三三不需要额外显示一条“特性来自奇梦咪”的说明。
4. 切形态不是使用一次技能，不自动加层，不重复执行撒娇等技能的累计效果。

这比上一版计划更简单：三三不需要记录“达到过首领后才获得永久特性”的过程。现有控件 ID 已相同，主要修复状态被重置，不另造迁移系统。

## 其他家族的处理建议

本次读取 `public/data/runtime.json` 与 `src/domain/trait-effects.js`、`src/domain/trait-runtime.js` 核对。本地族谱按 ID 连通分组有 201 组多形态家族，其中 58 组存在不同特性名称，合并重复变体后是 43 种特性组合。该统计仅用于发现审计对象，连通关系不代表任意两种形态都可直接萌化，特性规则也不是全部游戏机制的实测结果。

### 统一原则：保留原效果，不按新名字重新解释旧输入

分开保存原配置身份、本场形态、有效特性来源。普通萌化与还原只更新形态；特性来源不降级，已填参数不变。只有已核对的数值等价项允许直接使用新名称，三三属于这一类。

| 类型 | 本地实例 | 推荐处理 |
| --- | --- | --- |
| 名称不同、当前数值等价 | 鼓气 / 三鼓作气；鸭吉吉的挺起胸脯 / “国王”的威严均对能耗 1 技能增加 50% 威力 | 保留原参数，只计算一次；鸭吉吉的种族资质变化取目标面板，不额外再叠一份特性面板 |
| 同类效果、强度不同 | 波普鹿超级电池 +40% / 低阶蓄电池 +30%；烈火战神爆燃 +30% / 低阶助燃 +20% | 高阶萌化后保留高阶系数和层数。如波普鹿 2 层切低阶，仍按 +80%，不降成 +60%；也不因为切换多计一次入场 |
| 条件相同、触发倍率不同 | 霜翼领主破空 +75% / 低阶顺风 +50% | 保留有效特性和原先手条件。速度面板另行重算；不悄悄覆盖手动勾选的“先于敌方攻击”，不能把速度比较等同于完整行动优先级 |
| 高阶增加第二项效果 | 烈焰狂战士蒸汽革命每层威力 +10、物防 +5%；暗夜颅主扫荡每层魔攻 +20%、魔防 +10% | 萌化后整套保留，不能只留下攻击项而丢掉防御项；反向计算同样读取保留的有效特性 |
| 平行分支、增益维度不同 | 武者鸡斗技是固定威力 +30，绅士鸡指挥家是双攻 +30%；混乱鱿彩涂鸦与秩序鱿墨绝对秩序分别影响攻击和减伤 | 不把相同数字或相同层数当作等价，不自动跨分支迁移；保留当前分支路径。同族其他分支仍可普通载入，但不能伪装成无损萌化 |
| 已有特殊继承 | 棋绮后分支的棋契陛下已有“渗透（进化继承）” | 沿用现有继承来源和层数，萌化后也只计一次；不能把渗透带到棋祈督等其他分支 |
| 主要影响回复、能量、出招或回合 | 氧循环 / 深层氧循环、浸润 / 浪潮等 | 本轮不因切形态自动回血、回能、降耗或重新入场；现有通用参数照常保留，不把“保留输入”宣称为回合机制已全适配 |

### 不照搬参考站的完整首领化流程

参考站“本场最高形态特性”的做法适合已核对的升阶规则，但本期先实现用户要的手动萌化/形态对比，不引入整套升阶结算。对于非等价特性，即使选择了未到达过的更高形态，也只替换本场形态，继续沿用当前有效特性，并明确显示“特性沿用：超级电池”等简短说明；不静默把历史 20% 层数翻算成 30%，也不假装已经完成真正首领化。

要计算目标形态的原生特性，仍走明确的普通载入/预设入口。将来若扩展真正的首领化，再逐条核对特性升级及旧增益的处理，不作为三三上线前置条件。

### 数据边界与已发现的回归风险

- 特性控件 ID 并非机制唯一标识：助燃的“火系技能次数”、搜刮的“敌方聚能或换宠次数”使用同一个层数控件 ID。不能只按控件 ID、字段名或数值相同就认定可继承为新特性；来源和明确的等价白名单必须同时正确。
- 存在输入上限差异：最好的伙伴层数无上限，裁决目前为 20；蒸汽膨胀为 20，蒸汽革命为 99。萌化保留原有效特性及其校验范围，不能因低阶控件重建把原来的 25 层截成 20 层。上限本身是否符合游戏另行核对，不在本轮擅改。
- 迪莫首领变体还涉及首个技能替换为对应属性愿力冲击，不能因为攻防速增益相同，就自动换技能或混用其他首领分支。保留已配技能和当前特性来源。
- 部分低阶的族谱列表包含多个分支，但高阶列表只包含本分支；选择路径必须以原配置身份和已选分支为锚点，不能萌化到共享低阶后丢失分支身份。

## 实现拆分

1. **状态迁移与回归先行**：增加独立的本场形态切换通道，不调用重置式 `applyConfiguration`。先写失败用例：带威力、能力、特性层数的三三切气球猫，对方状态原样保留。
2. **形态/特性解耦**：保留原配置身份和分支，以轻量本场覆盖描述当前形态和有效特性来源；计算、面板、特性控件和说明读取同一解析结果。三三直接复用相同数值输入；其他家族优先保留原有效特性，不逐个强行映射为新特性。普通加载预设仍走旧通道。
3. **配置与分享边界**：接入现有撤回；页面恢复与计算分享按既有能力携带形态状态，旧数据缺字段时按未变形处理。仅切形态及其后续临时调整，不向低阶精灵预设或队伍写回；显式保存时必须保持名称、形态和配置语义一致，不静默落成别的精灵。
4. **小程序入口**：先接共用规则与已有搜索，补再打开时的同族候选；不得保留旧入口中无条件重置异常的旁路。同步核心后做 H5、原生和构建验收，单独提交。
5. **Web/桌面入口**：在主计算器同族候选上接新动作；保留现有键盘/鼠标选择。仅增加下拉分组提示和必要的特性来源说明，先出临时前后图确认后落样式。
6. **跨端收口**：核心同步一致性、分享往返、撤回、单/四技能模式与正反方向检查；分平台提交，不将 H5 验收代替小程序原生验收。

## 验收用例

- 双方均填非默认参数：三三侧威力 +20、能力 +2、鼓气 3 层，另一侧另填层数、印记与血量。切气球猫/逗逗，输入值均保持，基础面板和伤害改变。
- 反向把三三放防御方重复检查，确保该侧攻击与防御两条计算方向一致，另一侧不变。
- 撒娇的累计威力、叠势的连击条件、逐槽覆盖和技能顺序连续切换后保留；切形态不等于施放一次技能，不额外加威力/层数。
- 三三四形态互切，3 层默认始终是双攻双防 +60%；普通/首领加成没有双算，无额外永久开关或冗余来源说明。
- 波普鹿带 2 层超级电池切低阶，仍按双攻 +80%，不变 +60%，层数不因“换形态”自增；返回与撤回均一致。
- 烈焰狂战士带 25 层蒸汽革命切低阶，威力和物防两项都保留，层数不被截成 20；攻守方向及说明使用同一来源。
- 棋绮后分支的渗透继承只计一次，降到共享低阶后不丢分支身份；普通选择其他分支不复用旧分支的特性层数。
- 非等价特性的高阶形态对比明确显示仍沿用的特性，不把单次形态选择伪装成特性升级；显式重新载入后按目标原生特性建立新状态。
- 返回原形态、重复点当前项、撤回、刷新/分享往返、载入预设与换其他家族均走各自规定路径。
- 生命百分比、显式 HP、默认满血三种输入不过新上限、不无故满血；纯查看/取消下拉不改变状态。
- 原个人预设、低阶预设、队伍配置均没有被形态切换污染。
- 320/390px、桌面、4K，亮暗两主题：名称和特性来源不截断；小程序原生与 Web 分开验收。

## 本期不做

不新增独立萌化工具页，不做全自动回合引擎，不自动点击撒娇后退化，不顺带实现赤子之心全技能降耗/最低阶不可继续萌化/特殊解除萌化等完整机制。用户本次明确要的主路径是“手动切同族形态，配置和战斗加成不断档”。这些自动规则需另行核对后单列扩展，不能把本期的手动支持称为全量萌化支持。

小程序的已有原生登录和历史生产核心门禁仍是独立验收条件，实施时重新检查；当前计划不绕过它们。
