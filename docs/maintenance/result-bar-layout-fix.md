# 结果卡排版修复验收

日期：2026-09-11。用户截图为小程序 H5 的 1920×945 桌面布局，目标为右侧结果卡（约 x=1252、y=80、宽 320px）。修复不涉及 Web 计算器组件或伤害逻辑。

## 问题与修复

- HP 输入框外壳高 56px，实际输入内容只有约 17.6px，数字靠上。改为 40px 高并居中实际输入元素。Taro 会转换 `input` 标签选择器，因此使用其实际 `.weui-input` 类定位内部输入，避免只对外壳生效。
- 桌面详情箭头只有 44px，并被组件默认边距置于卡片中间。改成卡片内通栏的“查看伤害详情”按钮，显式清除默认边距；手机断点仍为原来的 44px 图标入口，隐藏新增文字。
- 保留现有卡片颜色、伤害层级、比例条、技能结果行与计算状态，没有新增装饰或改变公式。

## 检查与证据

- 新增 CSS 回归断言，修复前失败，修复后通过；全量小程序测试 438 项通过，最终内部输入选择器调整后另跑相关 64 项通过。
- H5 320、390、820、1024、1920px 结果卡内部横向溢出均为 0。手机动作宽 44px且文字隐藏；桌面按钮填满卡片内宽。
- 最终 H5 内部输入 `text-align: center`、高度 38px；40px 外壳内上下居中。输入 400 后可以打开详情。
- `npm run lint`、`npm run miniapp:build:prod` 通过；小程序主包 1,400,560 字节，版本仍为 1.1.14。
- 微信开发者工具原生手机模拟器启动成功，读回更新后的组件，底栏箭头点击打开详情；原生截图检查通过。平板宽度检查为 H5 820px，并非原生 iPad 实机验收。
