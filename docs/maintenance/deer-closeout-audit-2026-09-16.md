# 电鹿斩杀线收尾评估

> 后续状态：用户确认的四项修复和①②③界面调整已完成本地验收。最新结果见 [收尾修复验收](deer-closeout-fixes-2026-09-16.md)；以下保留原评估，不代表当前待修状态。

## 结论与边界

主流程可用，但不建议原样发布。应先解决保命特性的确定性误导、模板清空特性参数、负数输入及带入状态一致性，再做小规模界面收敛。本轮为评估：未修改业务代码，未提交、推送或发布，版本仍为 2.0.2。

范围为本地 `/dianlu`、主页入口和返回、共享内核编排、深浅主题及 320/390px 手机。没有开展小程序新增开发，没有进行线上部署、真实手机性能测试或完整安全审计。

## 发布前应处理

### 1. 保命特性不应被包装成已完整生效（高优先级）

- 已复现：火羽「不死鸟」、化蝶「化茧」均有保留生命或免疫致命伤害的说明，但防御特性视图没有剩余触发次数参数。开启特性时，内核仍可返回确定的致命结果，warnings 为空；专页进一步显示可击倒及最低层数。
- 证据：`src/features/deer/DeerPage.jsx:77` 无差别显示已启用；`src/features/deer/deer-model.js:132` 直接用伤害和冻结阈值判断击倒；`src/domain/trait-effects.js` 的间接伤害排除规则包含致命伤害与保留1血。诊断脚本 `tmp/deer-closeout-audit.mjs` 可复现。
- 最小收尾：先区分「已计入／本次无直接影响／未完整支持」。保命条件未确认时，不给确定的斩杀推荐，不让一键填入伪确定层数。若补完整支持，必须增加剩余触发次数，并覆盖单招及先发第二击，不能只改显示文案。
- 验收：保命未消耗、已消耗、关闭防守特性三态；化茧两次免疫；接先发与普通单招；冻结阈值下的边界。

### 2. 切耐久模板会顺带清空特性条件（高优先级）

- 浏览器复现：蹦床松鼠当前能量为5，点击「纯肉」，当前能量变为0。
- 原因：四个仅定义性格和个体的模板也调用 `applyDeerPreset`，该函数将缺省 `traitValues` 写成空对象，方向条件随后被清除。
- 位置：`src/features/deer/deer-model.js:64`、`src/features/deer/DeerPage.jsx:47`。
- 建议：耐久模板仅改变性格与个体；读取完整已存预设再按其实际字段更新特性参数。模板切换不应悄悄改变战斗情境。
- 验收：四模板切换前后能量、层数、触发开关、吞噬特性、HP、天气、冻结均保持；伤害只随配点改变。

### 3. 能力等级负数无法正常逐字输入（高优先级）

- 浏览器实测：攻击能力等级全选后依次输入负号、2，结果成为 `02`，即正2。负号中间态被即时转为0。
- 位置：`src/features/deer/DeerPage.jsx:32` 的 NumberField。
- 建议：复用现有草稿数值输入模式，允许空值、负号等编辑中间态，在提交时校验范围。层数应提交为整数。
- 验收：键盘输入-2、删除重填、粘贴、上下箭头、失焦、最小最大值；不能仅用直接赋值的组件测试替代真人输入。

### 4. 「当前配置」并不保证所有带入条件完全一致（中优先级）

- 诊断复现：攻击方已存每层双攻55，专页构造计算输入时改回默认40；`buildDeerInput` 重设所有非层数的电鹿特性控件。方向里同时存在旧覆盖值时，又可能走另一条优先级。
- 防御方非星陨负面印记也被替换成none，例如减速。此项已证明状态未保留，尚未证明在某个具体对局造成多少伤害偏差。
- 位置：`src/features/deer/deer-model.js:95`、`:117`。
- 建议：只覆盖本工具正在查询的层数和用户主动编辑的条件。不能支持的带入字段应明确标注，不应静默丢失。
- 验收：标准40%/30%、自定义加成、方向覆盖和预设值优先级；带印记/异常状态从主页进入，未操作时与主页同条件结果一致。

## 操作体验与美术

保留：计算器红蓝双方标识、相同性格个体控件、真实技能图标、独立返回入口、深色金色强调、大鹿影。美术方向已成立，不建议再增加粒子、动画或更多装饰。

三项视觉候选已用真实页面临时注入样式制作，未落入代码：

1. 配置区小幅减高：去掉防御方重复特性小字、收紧间距，参数仍直接可见。现在右卡明显高于左卡，桌面产生空白；手机技能主体在首屏以下。不要以重新藏起特性参数来换空间。
2. 折叠战斗条件显示生效值：当前自身HP49%、冻结4层时，折叠栏仍只有固定分类文字，用户容易忘记低血或冻结正在影响斩杀。显示非默认条件摘要；冻结条需可见图例，手机不能依赖鼠标悬停。
3. 窄屏逐层表改三列：320px时六列卡片出现「未击倒／单招击倒」逐字换行，虽然没有横向溢出，仍然不好读。手机主表隐藏列头后，也应补回「当前X层伤害」标签。

对比图：`artifacts/web-ux-deer-closeout/mockups-combined.png`。依据项目UI工作流，视觉改动需按编号确认。

其他体验建议：已存预设应区分内置常用和用户自存；显示先发补刀后可明确标记条件成立与否；离子火花与电弧直接显示2/3能耗，避免只写「不同能耗」；刷新会丢失专页临时修改，应明确这是临时副本，是否保存草稿属于后续可选项。

## 性能、工程和发布

- 当前每次setup变化重算八个候选各11层；仅改变展示层数也会重算全表。Node本机热运行中位耗时约57–59ms，补刀开启约84–89ms，不代表手机实测。优先把当前层数选择与全表计算缓存拆开，不必先引入Worker。
- 完整生产构建通过。客户端15.73MiB、CSS gzip52.27KiB、JS gzip330.43KiB，均超过软基线但未触发硬预算；JS原始总量1.05MiB已接近1.06MiB限制。应限制新增依赖和装饰资源。
- 电鹿模块为延迟加载。首次只访问主页后离线再进入专页，是否已经缓存延迟模块尚未实测；旧缓存升级、线上 `/dianlu` 直达/刷新、桌面安装包路由同样应放入发布验收，不能拿开发服务器可用代替。
- 没有新外部写入接口，预设只读、专页修改不写回收藏；入口返回与状态隔离测试通过。未做依赖漏洞扫描、完整安全或素材授权审计；沿用项目既有来源声明，发布时补齐新增素材来源记录。
- 历史验收文档中仍有旧八行、旧控件位置和旧失败数字。提交前应形成一份当前验收摘要，保留历史但明确已被后续结果替代。
- 工作树混有传动、小程序及预设等既有改动。最终需按功能逐文件审查和暂存，不能把本次收尾当成授权全仓发布。
