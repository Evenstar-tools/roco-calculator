# 国际服 Web 与中英日界面开发计划

日期：2026-10-16（Asia/Shanghai）。本轮交付为开发计划；未修改产品、提交、推送或部署。

## 已确认目标

- 沿用 `rococalc.top`，将既有 `/en/` 升级为正式国际服工具，默认英文；国际服同时提供简体中文、英文、日文切换。
- 国服与国际服可以直接切换；语言切换不改变服务器、数值、配队和计算结果。
- 海外首次访问通用入口时自动进入国际服；明确链接、分享和用户选择优先，不强制覆盖玩家意图。
- 两服数据与规则分别核验和更新，复用一套应用和可共用的计算逻辑。
- 沿用现有界面和“打开即计算”，不新增介绍门页，不恢复已删除的 SEO 导航、FAQ、品牌页脚及源码导流。
- 首期范围为 Web/PWA。桌面、小程序不增加国际服入口；共用核心受影响部分必须保持国服兼容。

## 3. 入口与切换方案

建议地址约定：

| 地址 | 用途 |
|---|---|
| `/` | 保留既有国服兼容入口，同时处理无明确目标的新访客分流，不做介绍中转页。 |
| `/cn/` | 明确国服入口，海外访问也不自动改服。旧 `/dianlu/` 等既有链接仍按国服解释。 |
| `/en/` | 正式国际服工具，默认英文，保留现有被分享和收录的 URL。 |
| `/global/zh-CN/` | 同一国际服工具的简体中文界面。 |
| `/global/ja/` | 同一国际服工具的日文界面。 |

保留 `/en/` 是已有入口兼容安排；内部统一用 `serverId` 与 `locale` 两个字段，不以路径中的语言字符串推定服务器。首期国服维持现有中文界面，不额外扩大为国服三语翻译工程。

界面在现有菜单/顶部合适位置放一个服务器切换入口、一个语言入口，并显示当前服务器及测试/数据版本。国际三语页面均能返回国服；切服恢复目标服自己的配置，切语言保留当前配置与未保存操作。英文和日文长文案允许合理换行，不压缩成难读小字。

自动进入逻辑：

1. 先解读分享目标和明确路径。两者冲突时展示冲突并让用户选择按分享目标打开或取消；不静默改数值。
2. 明确路径按 URL 指定服务器/语言打开，不因 IP、浏览器语言或历史偏好强跳。
3. 仅通用根入口、没有分享时读取已保存的选择；既有国服用户存档只在首次迁移时视为国服历史选择。
4. 无选择的新访客，优先用同域边缘接口返回的国家/地区做默认分流：大陆默认国服，其他可识别地区默认国际服。该映射是产品默认，不代表官方测试资格或服务覆盖范围。
5. 无可靠地区结果时，浏览器语言仅作启发式：中文优先国服，其余优先国际服；给清晰切换入口，不宣称这是准确定位。国际服内部语言按日语→日文、中文→简体中文、其余→英文选择。手动设置后不再用自动识别覆盖。
6. 地区判断超时不阻塞应用，按上述回退规则进入；不调用外部 IP 定位服务、不为本功能保存原始 IP。实施时核对现有 EdgeOne 能力后决定最小接线。

仅显式手动切服/选语言持久化为用户偏好；自动推断按会话使用，可在新访问重新评估。临时打开分享或明确路径，不自动覆盖之前的手动偏好，避免一次定位失败或分享访问把用户长期锁在错误服。边缘地区接口可优先评估现有托管的请求 GEO 能力，仍以实际项目验证为准。[EdgeOne 官方函数说明](https://pages.edgeone.ai/document/edge-functions)。

不得直接给根路径添加基于 IP 的永久重定向：旧 `#v1…` 分享片段不送到服务器，必须在浏览器启动时先判断，旧码默认国服；查询参数、分享片段不能丢失。地区分流结果不进入可被其他用户复用的公共缓存。正式内容 URL 保持稳定、提供真实切换链接，避免自动跳转阻断用户与抓取。[Google 多语言/多区域指南](https://developers.google.com/search/docs/specialty/international/managing-multi-regional-sites)。

## 4. 两服数据与规则隔离

采用一套应用、共用确定性计算核心、独立数据包，不长期复制两套计算器源码。最小运行环境包含：

`serverId + gameBuild + dataVersion + rulesVersion + locale + capabilities`

- 每服分别保存精灵数值、属性表、可用实体/形态、技能数值与技能池、特性、血脉/魔法、预设、导入映射、规则参数及证据。
- 共享内部实体 ID 只用于确认过的同一实体；不同服的游戏原生 ID 独立映射，不能以同名、同图或图鉴号强行配对。现有稳定 ID 不重建。
- 完整国际数据包独立生成。可以复用经验证相同的基础记录，但每次发布固化其具体来源版本；不得用“国际补丁覆盖最新国服”的运行时方式，避免国服更新暗中改变国际数据。
- 特殊差异用小范围、显式规则参数或按版本选择的规则实现，避免在各处散落服务器判断。属性倍率、等级/个体/性格公式、舍入、连击、状态、触发时机和上限都要核对，不只核对种族值。
- 所有计算入口共用选服环境：伤害、四技能、属性查询、技能检索、排行、配队、电鹿工具、传动、选择/轮班明暗，以及 CLI 验算。
- 国际服未开放的机制显示英文/中文/日文的“该版本未开放”；证据不足的计算显示“未验证”，不给伪精确结论。缺数据时不回退国服数值。
- 开放/已验证能力检查必须在计算入口执行，不仅禁用按钮；分享恢复、原生导入、CLI和工具调用都不能绕过，拒绝不合法输入时保留原配置。

数据核验顺序：官方公告与公开资料 → 合法可用的测试客户端显示/官方数据 → 可复现实战样本。社区资料只做线索或交叉核对。记录字段来源、游戏 build、采集时间与核验状态，支持后续补丁差异审阅。

先用一条完整链路验证数据获取是否可行：一个精灵的官方名称、六维、属性、特性、技能池、一个技能及实战结果。拿不到决定性样本时，继续做框架和界面，不扩建臆测数据流水线。

## 5. 中英日文本与官方名称

三语是首版国际工具的明确目标，不将日文推迟到不确定的“以后”。

- UI 文案抽成 `zh-CN / en / ja` 词典；实体展示词典按稳定 ID 维护名称、描述、形态、别名及来源。使用一个维护入口，避免散落三套名称表。
- 官方英文、日文名称优先采用对应官方版本。缺失项内部可用明确标记的工作译名，不冒充官方；国际正式可用实体的官方名覆盖要逐项验收。
- 国际中文可以保留已确认同一实体的国服惯用名，但规则描述必须翻译国际版本内容；不能把国服机制说明直接搬过来。国际服官方尚无中文时注明其为工具译文，而非官方中文客户端文本。
- 搜索支持三语名称及确认的历史别名；大小写、空格、连字符、日文宽窄字符做合理归一化。日文 IME 输入期间不能触发错误选择或清空搜索。
- 全部用户可见表面纳入：主体控件、弹窗、引导、加载/失败/空态、规则条件、公式明细、辅助工具、按钮提示、可访问性标签、复制文本、分享、导出图、导入错误、更新说明、页面标题与 PWA 名称。用户自填队名和原始导入正文不自动翻译。
- 内部逻辑不读展示名称或译文。短期可保留中文内部键以减小迁移面，但要隔离到数据规范化/兼容层；依赖中文描述的传动等规则，先产出结构化参数再展示译文。
- 沿用项目基础本地化校对，检查缺失键、占位符、术语、翻译遗漏及目标语言残留；三语长文案和日文实际画面人工验收。英/日页面不能用无提示中文回退掩盖漏译。

## 7. 开发阶段与通过条件

以下为实施顺序及初步有效工时估计，不是上线承诺；第三方资料、测试资格和实际规则差异不计入工时。阶段可交叉推进，但不能越过数据验证条件。

| 阶段 | 主要交付 | 通过条件 | 粗估 |
|---|---|---|---|
| P0 基线与来源 | 对齐最新生产/主线；复用现有英文交接；一条国际数据来源链及差异清单 | 能指出每项关键输入来源；未知项明确，不从旧脏目录开始 | 0.5–1天 |

建议里程碑：

- **10月27日前准备项**：P0/P1完成，P2达到可验预览；先用明确标记的测试数据验工程，完成已公开的官方词条。若完整数据仍不可得，公开页面继续如实说明范围，不开启错误国际计算或自动分流。
- **国际测试数据可取得后**：P3以一条完整计算链路先验，再扩到国际已开放实体和功能；主工具及常用规则通过后可交付“Global CBT”，其他待验工具明确不可用。最终仍需完成全体可达功能的三语目标。
- **正式开放节点**：功能/数据/语言/入口四项验收分别通过，再按当时用户授权执行发布；不把计划批准视为推送或部署授权。

## 8. 最小充分验收矩阵

- 数值：CN原有代表用例保持；Global使用真实客户端样本核对基础/取整/属性/技能/特性。修改显示词和描述后结果不变；同服三语的输入和数值结果相同。
