首轮发布 `632d07aa` 已经通过 Git main 自动部署，生产页显示 v3 和防御分支；旧档案中的伊雷龙43级、魔攻×1.3和660实测保留，敌方三档为599/660/721。云端CI亦已通过。

生产升级时发现旧 Service Worker 将新 HTML 与旧固定地址脚本混用，首次刷新报错，第二次刷新恢复。初次缓存补丁 `33fe477e` 已推送，但跨线程审查进一步指出：3秒更新超时后继续启动仍有慢网混代风险。本次继续修复：S5工具资源在线重验证、断网回退原URL缓存；独立工具页只在控制器明确回复支持新缓存策略后加载CSS与UI，旧控制器升级超时给出刷新入口。无控制器直接启动；已确认新策略的控制器允许离线启动。启动器使用策略版本查询串，防止先执行缓存中的旧启动器。资源依赖检查同时覆盖内联模块和延迟样式，避免验收漏掉工具依赖。最终生产回查记录保留在 `output/s5-v3-completion-20261107/`。

新增真实 Chromium 升级回归：CacheStorage 保留旧启动器、UI、CSS和catalog，新SW实际安装延迟超过3秒；确认显示刷新提示、没有发出CSS/UI/data请求、旧脚本未执行且旧缓存仍在。安装放行后确认新策略、刷新可进入完整S5界面，再断网刷新亦成功。该用例已纳入正式S5浏览器门禁。

并行回归另复现新SW已安装却处于waiting、旧controller仍控制页面。已去掉register后的重复update；刷新时核对waiting身份与S5策略，再明确请求激活，最后仍以controller策略应答为放行条件。未知waiting不激活。接管完成后将本页HTML和带策略版本的启动器补进新缓存，支持升级后立即离线刷新；补取仅限同源、设有时限，失败不阻断正常界面。
