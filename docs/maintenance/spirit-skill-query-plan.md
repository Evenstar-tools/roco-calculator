# 按精灵查询可学习技能：实施计划

状态：2026-09-09 用户已确认方案 2 并要求开发，当前已实施并完成本地验收，见 `bidirectional-skill-query.md`。以下为早期讨论记录，其中四主标签、桌面卡片网格由最新双向查询／技能表方案替代。范围为 Web 与同源桌面，小程序不纳入首批，不推送、不打包。

## 目标与现状

让玩家选择一只具体精灵／形态，查看其全部可学习技能及学习条件。现有「老精灵新学」只列相邻赛季增加的学习关系，不能充当完整技能表。

已核查 `src/features/skill-query/SkillQueryPanel.jsx`、`catalog.js` 与当前 catalog：S3／S4 两个赛季，当前 S4 有 619 条精灵记录和 619 条学习面记录；现成字段包含技能效果、能耗、威力、种类、属性，以及默认学习、等级、血脉和技能石学习信息。字段存在不等于所有具体数值完整，缺失项继续显示待补充，不能填 0 或自行推测。

## 推荐入口

现有弹层保留，顶部改为「按技能｜按精灵｜赛季新技能｜老精灵新学」。原「技能查询」改名「按技能」，不删除任何原查询功能。首次仍进入原按技能视图。

「老精灵新学」的精灵名可跳转到对应精灵完整技能表，携带查询赛季；跳转后默认显示全部技能，本季新增学习关系标记「新学」，避免把新增列表误认作全部技能。

## 查询与展示

1. 搜索精灵：复用现有名称、图鉴号、拼音及社区别名搜索规则。按家族合并候选图，只展示一个代表头像；命中具体形态时直接定位该形态。
2. 选择具体形态：详情头部显示头像、完整名称、属性和形态切换。查询结果只属于当前形态，不能把整个家族技能取并集算给一只精灵。
3. 查看技能：卡片包含图标、名称、属性、物攻／魔攻／防御／状态、能耗、威力、实际效果，以及学习来源／条件。保留正常字号，不照搬参考图的整套皮肤或大块装饰；不展示不影响配招的背景文案。
4. 筛选：技能名称／效果搜索、来源（默认／血脉／技能石）、种类、属性；默认全部。来源与种类显示数量，按唯一技能计数，同技能多途径只显示一张卡，列全途径。多个来源分类之间可能重叠，分类数量不强行相加等于总数。
5. 排序：默认先显示默认学习技能并按已知等级排序，再显示血脉、技能石；多来源技能以默认学习优先排序，不遗漏其他途径。缺失等级不伪造。
6. 详情与返回：点卡片展开完整效果／学习条件，也可查看其他可学习家族；返回恢复原精灵、形态、筛选与滚动位置，不修改计算器当前攻防配置。

## 自适应布局

- 桌面：左栏精灵搜索与候选家族；右侧精灵信息、紧凑筛选、技能卡片网格。根据可用宽度排 2–4 列，不硬挤五列。
- 手机：先选精灵，再进入技能页。顶部保留简短精灵身份与返回；技能卡片默认单列，效果直接可读；筛选集中折叠展示，有生效条件时显示摘要，避免属性选项长期占满首屏。
- 继续沿用现有头像尺度、亮暗主题与字号体系。首次未选择精灵时不自动填充示例内容。

## 实施步骤与验收

1. 先出 1440px 桌面、390／320px 手机的前后对比图，包含多形态选择、长效果和多学习途径；用户确认后再实施。
2. 数据层增加按精灵 ID 查询和筛选计数的纯函数，复用现有 catalog 与缓存，不新增一套手工学习面。赛季选择仅提供已有数据，不能混用当前赛季学习面和旧赛季技能说明。
3. 接入新视图和旧「老精灵新学」跳转，保持原技能反查流程与返回状态，独立提交，支持整批回退。
4. 用迪莫、鸭吉吉多形态、首领／进化形态验证：全部技能与学习面一致，形态不串技能，默认／血脉／技能石过滤准确，新学标记来自学习关系变化而非技能首次出现赛季。
5. 自动测试覆盖别名定位、多来源去重、计数、缺失字段、跨赛季、返回状态；实测桌面和 390／320px 亮暗主题，无横向溢出、不缩小字号。最后运行全量单测、浏览器测试、代码检查、构建体积门禁并读回截图。

## 暂不扩展

不自动加入配招、不修改热门预设、不覆盖当前计算配置、不增加无数据支持的赛季或解锁规则。本次计划不代表已实施或已发布。
