# 测试精简与打包验收

## 结论与范围

日常验收改为关键集合，重复/低价值历史用例删除，其余专项按改动范围运行。产品代码、计算公式、版本号和发布资源没有因本次精简而改动；此前未提交的标题栏与萌化标识修改原样保留。

原 `npm run build` 本身不运行全量单测或浏览器测试。实际冗余来自发布前全量验收，以及 CI 的 validate/e2e 两次安装、两次构建和重复核心校验。因此本次降低的是验收与 CI 成本，不声称单次压缩或安装包生成变快。

## 日常与专项

- `npm test`：全部 `tests/domain`、`tests/state`，关键数据/离线缓存/发布记录，以及萌化、宽窄屏模式、撤回、队伍导入、电鹿、属性查询、传动等关键组件。纯逻辑使用 Node，交互使用 jsdom。
- `npm run e2e`：十一条真实浏览器链路，涵盖真实二维码个体恢复与导出、旧存档、离线重载、双向技能查询与失败重试、特性/异常状态计算、单技能持久化、传动、宽窄屏速度分析和应用配置。默认先从源码构建。
- `npm run test:full -- <测试文件或目录>`：维护对应组件、导入器、构建/发布脚本时使用；省略路径则运行全部保留的单元/组件专项。
- `npm run e2e:full -- <测试文件>`：修改布局时运行相关专项；大范围交互改版时省略路径运行全部。完整浏览器集合仍可枚举到 176 项。

清单入口为 `config/vitest.release.config.mjs` 和 `config/playwright.release.config.js`。新核心计算/存档测试自动进入日常集合，新增重要 UI 功能应更新关键清单。不要把只在专项中的文件传给 `npm test`，请使用 `test:full`。

## CI 与打包

- validate 构建一次并运行关键单测及浏览器验收，浏览器通过 `E2E_PREBUILT=1` 使用本工作区刚构建的产物，不再重新安装和构建。
- 保留 validate、miniapp、e2e 三个原有状态检查名称。e2e 汇总依赖 validate 成功，失败/取消不会报绿，不再重复执行浏览器用例。
- 去掉 validate 的重复数据生成/验收/核心检查步骤和 miniapp 的重复前置核心检查。实际检查仍由 build、miniapp:test 执行。
- 小程序独立测试和生产包校验未精简。实际数据一致性、资源绑定、验收证据、共享核心和体积上限均保持。
- 本地 `npm run e2e` 已构建，无需紧挨着再跑一次 `npm run build`。仅打包仍用原命令。

## 本地验证

测试采用两个 worker；时间是本机实测，不等同于远端 CI 耗时。

| 验证项 | 结果 |
| --- | --- |
| 精简后的单元/关键交互 | 103 文件，1774 项通过，Vitest 报告 69.20 秒；不含 npm 前置核心检查 |
| 浏览器关键链路（从源码构建） | 11 项通过，Playwright 报告 38.8 秒，构建所有硬门禁通过 |
| 浏览器关键链路（复用同次构建） | 11 项通过，Playwright 报告 13.6 秒；整个命令实测 14.63 秒 |
| 数据校验 | 622 精灵 / 581 技能，重复形态与种族值不匹配均为零 |
| 相关保留专项补查 | 构建、验收矩阵、共享核心/发布门禁、电鹿剩余用例及缓存性能，13 文件 / 207 项通过 |
| ESLint / CI YAML / 差异空白检查 | 通过 |

专项补查发现并修正一条旧断言：原断言强制 CI 单独重复执行验收；现检查 CI 只构建一次，且 build 仍包含验收门禁。电鹿拆分前后的 25 个测试块逐字比对，每块恰好保留一次。

旧发布记录（`artifacts/release-2.2.2/web-acceptance.md`）为 176 单测文件 / 2653 项、194 浏览器项；仅用作范围对照，本轮没有再次完整运行旧流程，因此不报告同机严格耗时降幅。

构建体积仍有原有预警：JS gzip 343.94 KiB / 上限 344 KiB，CSS gzip 54.68 KiB / 上限 55 KiB，未提高阈值。后续新增产品代码仍需注意预算。
