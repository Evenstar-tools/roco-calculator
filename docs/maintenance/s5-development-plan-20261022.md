### 10 月 22 日战斗修复：进入 S5 前的核对项

| 官方长图事项 | 计算器应核对的内容 | 处理边界 |
| --- | --- | --- |
| 不朽精灵受掉包影响后，力竭复活时技能威力异常 | 当前是否支持增减益转换、复活后状态恢复、威力来源及重置；现有「掉包」是增益转对应减益，不是交换技能 | 只有确实模拟到该事件时修实现；不扩写完整复活事件系统。 |
| 晴天下光系精灵未获得亲和效果 | 现有天气、属性及亲和条件是否符合修复后结果 | 根据正式说明与实测判定；不直接猜测新的倍率。 |
| 起飞加速首次技能被打断后，本场无法再次触发 | 首次触发资格、被打断与已成功触发的区别 | 检查当前输入/状态是否能表达，补具体漏测场景。 |
| 战斗外首领化伊兰龙处于蓄力状态时，其他技能能耗未降低 | 形态身份、蓄力条件、能耗与传动工具的关联 | 不把一次客户端修复自动解释为所有蓄力技能的通用规则。 |
| 领地试炼余烬飘字、部分野生/奇遇精灵释放彗星 | 与当前 PVP 工具是否存在真实数据或规则交集 | 纯表现或野外 AI 问题记录为不涉及；有交集才补任务。 |

官方同批还有精灵盒子筛选和批量标记相关优化，包含个体资质等条件；这不能证明原生阵容编码协议同步变化。导入协议仍须用完整真实分享码及对应 UI 验证。

当前基线的静态定位：不朽、起飞加速的特性记录尚无 `ruleId`；现有天气枚举未纳入晴天/亲和；伊兰龙「游弋」已有蓄力双防效果，未发现上述其他技能降耗实现。因此这四项先做支持范围与正式规则核对，不把客户端修复公告直接变成新增状态机或猜定参数的依据。此结论来自源码与数据检查，尚未做游戏实测。

## 3. 从 S4 继承的处理方式及必要改进

| S4 实际经验 | S5 采用的方式 |
| --- | --- |
| 前瞻先录入可确认的身份/图片，部分幼体和技能数据留空；正式日再补完 | 候选与正式分开。未知数值用空值和现有不可计算状态，不补 0、复制上一形态或猜 60 个体。 |
| 正式期从旧 BWIKI/CSV 链路切换为 NRC 六模块 | 优先复用 `nrc-source.mjs → apply-nrc-current.mjs` 的现行路径；补正旧 runbook 的入口，避免走回旧构建器。 |
| 旧玩具从前瞻威力加成改为正式双攻增益 | 前瞻与正式逐字段、逐规则复核；相同名称也要核机制。不得仅替换赛季标题。 |
| 满月砣拆出上下弦、更名保留 ID；旧占位技能退出当前学习池但保留存档兼容 | 稳定 ID 与新形态分开处理；历史兼容实体不能混回当前可学习列表。 |
| S4 学习池不叠加过期 S3 关系，传说技能限定具体形态 | 当前学习面由 S5 审阅数据生成；S4 用于差异和历史查询，不能直接做并集。 |
| 季中修复“实际变化叹号优先、新实体 NEW” | 沿用现有提示优先级；新赛季不把所有旧精灵重新标 NEW。 |
| 小程序原始包未超 2 MiB，但上传预处理后超限 | 沿用已有 192 KiB 余量门禁；S5 新图单独压缩验收，实际上传为独立阶段。 |
| 跨部署缓存短暂拿到旧数据 | 保留缓存和存档做正常升级回归；核代码/数据/规则身份一致，不能用清缓存冒充升级成功。 |
| 主题、随机、经典配色已有独立偏好 | 保留用户选择；S5 加入可选和随机集合，经典配色继续沿用已确认的 S4 基础色。 |
