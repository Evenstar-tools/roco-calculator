# 附异常攻击直接预览：排查与完整修复计划

日期：2026-09-30；基线：`3661e5b`。用户已追加授权“处理完成 同版本上传更新”；本计划已实施并完成同版本交付：Web／Windows 2.2.4已上线、回查与Release下载核对，小程序1.1.19已生产构建、原生验收及开发版上传；未提交审核或正式发布。以下“当前结果”和代码行号保留为修复前诊断记录，详见[本轮交付记录](attack-status-preview-release-20260930.md)。

## 目标与边界

攻击技能的结果代表“按当前配置出招一次”：选择后立即查看，不需要再点一次使用。负面状态结算关闭时不追加异常结算；开启时将本次技能及满足条件的特性附异常一并预览。查看、切换、重复点击不改变战斗状态。

本次不改变伤害公式、冻结斩杀规则、异常实际扣血上限和原有免疫判断；不将纯状态、防御、天气或准备技能默认为已使用。正面强化、选择/持续成长、特性战后结算与连续回合推演仍需要真实操作，不能因查看结果自动提交。

## 本次证据

本地 Web 实测，圣代甜甜（樱桃巧克力口味）→寂灭骨龙，目标425 HP，行动前异常均0，开启结算：

| 场景 | 当前结果 | 问题 |
| --- | --- | --- |
| 寒潮初次查看、点右侧结果行 | 372／87.5%，没有本次冻结 | 附异常被漏掉 |
| 点寒潮正文第1次 | 372／102.5%，冻结3层／15%斩杀线 | 正文点击才隐式启用 |
| 第2次、第3次 | 102.5%、回到87.5% | 查看动作变成应用/取消循环 |
| 单技能旧次数0／1 | 87.5%／102.5% | 单技能也依赖四技能1号槽旧次数 |
| 暴风雪旧次数0／1 | 157／36.9%与51.9% | 不限于寒潮 |
| 关闭结算、旧次数1 | 寒潮仍372／87.5%，不显示异常结算 | 总开关正常，额外次数门槛才是问题 |

本例冻结3层来自寒潮1层＋加个雪球2层，直伤仍372，不将冻结斩杀线伪造成额外伤害。

真实复现：`output/playwright/attack-status-plan-20260930/reproduce.js`、`probes.js`，截图`initial.png`、`activated.png`。规则扫描/解析器检查为静态与程序证据，不等于逐个技能的实战验证；诊断阶段没有微信原生验收，实施阶段的原生与发布验收另行记录。

## 根因与影响范围

1. `src/domain/calculator-view-model.js:358–371`：已解析本次技能＋特性异常，但统一要求`negativeStatusUseCountsBySlot[槽位]>0`才加入结算，没有区分攻击预览和纯状态触发。
2. `src/App.jsx:923–950`与两种四技能编辑器：技能正文点击循环`0→1→2→0`；选技、聚焦、结果行只选中。同一技能不同点击位置结果不同。
3. `src/domain/skill-damage-ranking.js:177–196`：冻结承伤榜重复了同一个次数门槛。不能只移除界面按钮。
4. 单/四技能切换保留方向上下文，单技能又读取槽1次数；四技能换技能清该槽次数。旧记忆、正反方向、分享可产生不同预览。
5. 小程序共享同一门槛，查看入口主要做选择，不写这个次数；并非 Web 局部显示问题。小程序现有显式使用入口须单独回归，不能用自动攻击预览掩盖纯状态入口缺失。

## 覆盖清单

当前规则明确支持的15个攻击异常源全部纳入，不对名称逐个补丁：

| 类型 | 技能 | 保留的条件 |
| --- | --- | --- |
| 灼烧 | 易燃物质、炙热波动、烈焰风暴、花火 | 炙热波动应对分支；易燃物质逐击追加 |
| 冻结 | 暴风雪、极寒领域、滚雪球、寒潮 | 极寒领域仅条件满足时翻倍；滚雪球/寒潮应对分支 |

| 中毒 | 毒针、腐蚀酸液、连续毒针、毒囊、毒液渗透、虫群 | 毒囊应对；毒液渗透读旧毒；虫群按输入奉献层数，默认0；连续毒针逐击追加 |

11个特性来源同样覆盖：电子音乐、生物碱、高浓生物碱、灵魂灼伤、毒腺、加个雪球、贪心算法、爆裂玉米、溶解扩散、溶解腐蚀、扩散侵蚀。分别保留天气、技能属性、实际能耗、技能槽位、携带毒技数量、目标中毒印记及确实施加冻结等条件。寄生攻击目前来自特性，不凭空新增攻击技能寄生规则。

只读既有异常的冰冻光线、碎冰冰、冷凝、感染病、以毒攻毒、鸩毒、腐化、疫病吐息、不可接触、过敏原不当成新的状态施加来源；中毒印记不等于中毒状态。

纯状态施加技能（孢子、引燃、充分燃烧、天火、焚烧烙印、野火、霜降、霜天、冰点、打喷嚏、毒孢子、毒雾、剧毒、捆缚、星火）、防御技火焰护盾/冰墙，以及惊雷、重金属粉尘保持单独触发/条件语义。打喷嚏逐击追加作为连击同类回归检查，不改为自动已使用。

## 实施顺序

### 1. 先锁定真实故障，再改共享预览

在现有 VM/应用集成测试中增加“开启结算、初始次数0、直接选中寒潮/暴风雪就有本次冻结”的失败用例，替换攻击被旧循环控制的断言；纯状态显式触发断言单列保留，不另建测试框架。

复用现有异常来源解析与结算，加入一处共用的“本次预览是否包含施加”判定，主结果和承伤榜共同使用。攻击类别及有效解算状态决定资格，不以`totalDamage>0`判断；合法的零伤害/免疫攻击仍按原规则处理其附异常。开关关闭不追加结算。

计算顺序保持：行动前配置算直伤→解析本次条件与附异常→既有异常＋本次追加→结算。每一技能行独立从同一行动前基线计算，不叠加四行；不反写全局异常层数、HP、能力等级或应用历史。读取旧冻结加威力的技能不能提前使用自己本次新挂的冻结。

### 2. 解除隐式点击，保留真正的行动操作

Web精简/具体、单/四技能的选技、结果行、参数聚焦和正文重复点击均只查看攻击结果，停止为攻击循环负面次数、显示“已用/取消异常”提示。不能用聚焦时写入次数1的补丁。

`activateFourSkill`还承担强化、选择/持续成长、吸血后掉血和贪得无厌等战后提交，必须逐分支保留。若某攻击确有独立“应用后续变化”功能，用明确的小操作入口承载，不再借正文查看暗中提交；不默认增加所有技能的使用按钮。入口资格不能仅用`canApplyBattleActivation`判断，还须涵盖计算结果的`postAttackEffects`、特性和成长等真实后续分支，避免丢失原提交入口。

高级选项仍填“行动前已有层数”，删除攻击技能旧三次点击指引；纯状态/防御技能明确使用的条件与功能保留，不因内容减法删除。没有可显示的结算信息时不留空的“状态结算”卡；有效状态摘要完整保留，不截断也不直接删掉。

### 3. 将灼烧下回合预估单独表达

仅在已有灼烧、可继续预估且未击倒时，在现有下回合区域使用一个“下回合继续此技能”勾选。默认不续用，勾选只改变下回合投影，不能重复加本回合层数/伤害。取消勾选不取消本次攻击附异常；其他异常不显示下回合面板。

该条件随方向及技能身份隔离，切技能重置；不使用技能正文的第2次点击表达。旧次数只有槽号、没有技能身份：仅在当前四技能模式中能核实本槽原技能时，旧2才可兼容为续用预估；单技能继承的槽1次数不得推断为当前技能续用，无法匹配均默认不续用。0/1均按本次一次攻击预览，不能把2解释成本回合两次。不为这个显示投影改写战斗基础配置。

### 4. 修逐击追加与旧配置兼容

易燃物质、连续毒针当前分别固定灼烧4/中毒2，打喷嚏固定冻结3，改变连击输入仍不变。只对描述明确“每次连击”的规则传入现有解算的有效连击次数，默认连击保持原结果；上限/特性修正后的次数优先，不能用未归一化输入数，也不能把其他技能、特性的“每次使用”一律倍乘。实施前逐条核对当前数据描述，不猜未知规则。

攻击当前预览忽略旧使用次数0/1/2，纯状态保留其触发兼容；新操作不得制造跨模式/跨技能历史残留。分享和持久化摘要不再把旧2写成“本回合应用2次”。沿用已验证分享开关边界：分享预览按传入开关，但不改本机偏好；继续、返回、恢复原样保持现有语义。若新增可分享字段，必须同步字段白名单、旧端提示和版本兼容，不静默丢参。

### 5. 同步所有结果入口并验收

复用共用结算结果，同步技能编辑行、结果卡/列表、手机底栏/抽屉、冻结承伤榜及小程序。承伤榜继续逐个候选解析免疫/条件，仅直伤＋冻结斩杀线，不顺手纳入其原本排除的回合末扣血。使用共享镜像同步入口，不手工改一份镜像。

Web和小程序按平台分批实施、独立提交；小程序实际构建与原生运行确认后才能声称兼容完成。桌面复用 Web 逻辑，发布时再验安装包；发布依据用户后续明确授权，不从最初诊断请求推定权限。

## 实施收口

- 单技能次数、续用均使用独立 `single` 键；四技能沿用现有1–7槽，续用同时核对技能ID，无法归属的旧单技能槽1次数不迁移。单技能结果列表也改为读取实际所选技能，避免展示四技能第1槽摘要。
- 纯负面技能保留“使用状态／取消使用”；带正面效果又由特性附异常的混合技能保持“使用技能”，重复使用正常增加强化，异常预览仍只按本次一次，整次行动走原撤回。不以第二次使用误取消正面行动。
- 小程序采用同一资格判定和实际特性解析，负面结算开启时不自动使用纯状态或混合技能；关闭时保留原有正面状态技能入口行为。灼烧续用只影响下回合预估。
- 新分享协议v4保留续用身份与单技能参数；开启异常结算的分享也使用v4，避免旧接收端仍按“未使用”得出不同结果。未使用新语义的旧链接继续兼容，超长降级仍明确提示核对。
- 本地真实 Web 已核对寒潮首次372／102.5%、关闭87.5%、暴风雪首次157／51.9%，重复查看不取消异常，灼烧勾选不改变本回合。实图位于 `output/playwright/attack-status-preview-20260930/`，非真机验收。

## 验收矩阵与停止条件

| 检查面 | 通过条件 |
| --- | --- |
| 15个攻击源＋11个特性来源 | 开关开时初始直接预览一次；条件满足/不满足分别正确，关闭保留原直伤 |
| 既有层数0/非0、免疫、直接击倒 | 新旧层分离、不重复应用；冻结只给斩杀线，实际扣血与击倒结论一致 |
| 查看操作、两种模式、两个方向 | 选择/结果行/正文/参数编辑同条件同结果；反复查看不增加层数、次数或撤回历史 |
| 旧次数0/1/2、换技、刷新、分享 | 攻击当前预览一致；纯状态触发、续用投影及分享开关边界不串用 |
| 连击默认/改1/改多次/有效上限 | 逐击规则按有效次数；单次来源不倍乘；默认原值不变 |
| 主卡、四行、底栏、抽屉、榜单 | 本次异常、百分比、伤害和结论一致；榜单口径不扩大 |
| 正面强化、成长、战后结算、纯状态/防御 | 查看不自动提交；原明确操作仍可用、可撤回 |
| 实图与平台 | Web1920及320/430亮暗关键操作、独立视觉复核；小程序生产构建和原生路径，未做真机则明确标注 |

寒潮验收锚点：本例开启后首次即372／102.5%、一次冻结击倒，关闭仍372／87.5%；无额外点击。暴风雪开启后首次157／51.9%，关闭36.9%。默认条件与免疫分支还要各自核对。

## 单独登记、不得混入本轮猜算的缺口

大雪球、下黑手、抓到你了、焰色反应、蚀刻、毒牙、重金属粉尘及切换免疫类当前有审计分类，不代表其全部战斗事件已实现。它们需要历史事件、进退场或转换机制输入，后续各自定位来源与验收条件。当前关键词扫描未发现未分类条目，但不能据此宣称所有技能已经完整适配。
