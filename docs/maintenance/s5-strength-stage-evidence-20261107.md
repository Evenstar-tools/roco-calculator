当前安装包覆盖至 `_12_P`。PETBASE 的有效 schema 来自 `_5_P`，数值来自 `_6_P`，dev_CN 名称来自 `_4_P`；不能用旧 `_0_P` 数值替代当前覆盖结果。

`PETBASE_CONF.stength_stage` 的原注释为“种族资质（只有1阶就填3，有2阶填2和3，有3阶填1，2，3）”。另一个 `stage` 字段用于形态显示，两者分别核对。

- 包体表1302条；工具目录694条。

- 28条占位保持未确认，未纳入通过数；没有给它们补猜测阶位。
- 当前运行目录和防御映射的阶位均为零差异，因此本轮没有改任何阶位数字。
- 313条界面形态与强度阶位不同，其中普通精灵245条、首领68条。这些是两个字段的实际差异，不按“一阶”批量改成强度1。
- 仅有两条未进入可用目录的NPC缺少原始阶位，审计保留空值。

`data/reviewed/s5-strength-stage-audit-20261107.json` 保存完整字段投影和逐项结果。`node scripts/audit-s5-strength-stages.mjs --offline` 可离线复核；`--apply` 幂等更新来源元数据，不调整数值。`verified` 只说明原始阶位核验，不说明伤害公式已还原。

## 当前系数与证据边界

攻击按本形态种族和强度阶位拟合，阶段1/2/3分别为2.8/2.4/2。防御沿用普通家族终点双防种族、连续表达式及以下回退：

| 强度阶位 | 物防回退 | 魔防回退 |
| --- | --- | --- |
| 1 | 1.806 | 1.806 |
| 2 | 1.65725 | 1.6005 |
| 3 | 1.38531 | 1.335 |

以上均为经验模型。固定“终点种族、连续表达式、每阶段一个物防c”在现有条件记录中已经出现冲突：

| 阶段 | 相冲约束 |
| --- | --- |
| 1 | 历史可爱猿 c≤1.808768764；实录沉金中性 c>1.823432231 |
| 2 | 历史伊雷龙 c>1.657143511；小翼龙 c≤1.643053916 |
| 3 | 历史鲸条件点 c>1.385292035；噼啪鸟中性 c≤1.384539732 |

这些是对特定模型结构的反例；鲸等历史条件包含反推输入，证据强度不同。结果不证明游戏必须每物种一个c，也未排除本体种族加取整的结构。只换三个常数不能据此宣称全种公式校准。

保留已有源ID有限校准：小翼龙3209物防1.643只在42级不变/加物防有样本；星尘虫3398的42级不变有效防御174以克制修正1.8为条件；噼啪鸟3444的42级不变137/43级减物防126；沉金兽3802的43级不变254。精确点按原有源ID、等级、性格、种族和阶位匹配。不同觉醒/血脉状态未参与运行时匹配，仍属条件拟合。

100条历史 field-samples 全标referenceOnly，其中仅8条记明受击防御；不能补默认面板将其包装成100条实测。22条实录含6条自损，另有缺威力/状态和残留失配。本轮没有改实测数字、放宽容错或宣称原始公式总门禁通过。
