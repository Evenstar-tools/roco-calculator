# Web UX23 计划：属性查询信息收纳与双属性精灵

日期：2026-09-22
阶段：implemented（本地实现与验收完成）
基线：`d7505a1`
范围：Web 属性查询弹窗；不涉及小程序、桌面、计算公式或线上部署。

## 观察

用户截图中有两处低价值重复说明：

1. “防守抗性”右侧的“别人打我”和“进攻打击面”右侧的“我用这两系打谁”，与标题下已有说明重复。
2. 底部“点击结果查看倍率来源”说明条只是在解释点击行为，占用了一整行；用户希望把空间用于查看对应属性精灵。

## 方案

### UX23-01：删除重复辅助文案

保留两列标题下的具体说明，删除标题行右侧的短句：

- 保留“地 / 冰作为防御属性 · 优先看弱点”。
- 保留“针对 18 种单属性 · 两系取较优倍率”。
- 不改倍率分组、点击 chip 查看来源的行为。

### UX23-02：双属性时显示对应最终形态

当且仅当选择了两种属性时，在原说明条位置展示“对应属性精灵”区域；单属性选择不显示该区域。

- 按两种属性精确匹配精灵的双属性组合。
- 复用项目现有形态清单，只展示 `formRole=final` 的已确认最终形态；不把成长形态或首领形态混入结果。
- 卡片显示最终形态名称和属性；无候选时显示空状态。
- 该区域只做查询入口，暂不叠加技能、伤害、性格或推荐结论。
- 原“点击结果查看倍率来源”说明移到倍率 chip 的 tooltip/可访问名称中，避免丢失可解释性。

## 实施前验收口径

- 选单属性：不出现“对应属性精灵”区域。
- 选双属性：只出现最终形态；同一进化链不重复。
- 地＋冰：显示“獠牙猪”这一最终形态候选；若数据更新，应按数据自动变化。
- 清空或替换任一属性：卡片区域同步隐藏或刷新。
- 原倍率 chip 仍可查看来源；键盘焦点、Esc 关闭、亮暗主题和 320/390px 不溢出。
- 已补组件/领域测试，并完成 1280×760 与 390×844 本地页面验收；未发现横向溢出。
