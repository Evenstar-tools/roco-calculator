# 技能查询数据维护

## 更新 S4 内容

沿用现有数据维护流程更新 `data/snapshots/current.json` 中的技能、精灵和学习关系，然后运行 `npm run data:skill-query`。开发启动和 Web 构建的 `data:runtime` 已包含此步骤，无需改查询 UI。线上仍需正常提交、部署，正在打开的旧网页需要刷新，不是实时读取飞书。

生成资源：`public/data/skill-query/catalog.json`。映射报告：`output/skill-query/data-report.json`。未知能耗/威力保持 `null`，不要填零占位；真实零值会显示为零。

S1—S3 技能归属赛季继续使用 `data/skill-query/bwiki-seasons.json` 的历史 BWIKI `data-param6` 证据；S4 当前资料改用新站 `nrc` 的固定版本模块，全量收录 579 个正式技能。与 S3 的 553 个技能比较得到 26 个 S4 新技能，包含麦芒，不再混入降雨、午夜爆音两个未收录占位。旧站赛季导入脚本只用于核验历史，不作为当前学习表来源。

普通查询顶部为“所属赛季”筛选，默认全部赛季；“赛季新技能”按技能归属筛选，未保存 S2 快照也不影响列出 S3 的 57 个新技能，并复用运行时技能图标；缺图或加载失败时显示属性图标。“赛季学习更新”（原“老精灵新学”）使用相邻快照比较，同时展示老精灵新增学习关系与新技能的已知学习面。新精灵只计入新技能关系，不将其全部旧技能误报成赛季新增。菜单入口为配置组最后的“技能检索”。

### 后续 BWIKI 新技能核验

每次检索到新技能，不只补技能名称、效果、能耗、威力、归属赛季和图标，也要核验可学习精灵及学习途径。将有来源依据的关系写入当前快照，保留对应页面、修订号或抓取时间等证据，再生成查询资源；“赛季学习更新”会自动纳入这些关系。核验学习面时区分具体形态，不凭家族关系扩散给全家族。

技能已确认但学习面未确认时，保留待核验项，不猜测绑定、不将“未收录”表述为“不能学习”。缺少历史学习面的老精灵只展示可确定的新技能关系，不把已有旧技能全部判为新增；历史漏录的旧技能关系应补回基线，避免误报本赛季新学。已有赛季基线不得为了当前展示而随意改写。

家族代表改为最早可学习形态，不能学的幼体不作为代表；途径筛选后按匹配形态选代表。页面内缓存预取结果，菜单打开时预取代码与资料；重新打开无需重复下载或解码，失败可重试，网页刷新后重新获取。

## 新增后续赛季

先冻结上一赛季快照，将 `data/skill-query/seasons.json` 中上一赛季的路径指向冻结文件，再追加新赛季和快照路径，并设置 `currentSeason`。清单按时间从旧到新排列；界面对比所选赛季与其前一赛季，合并老精灵新增关系与新技能学习面，同一精灵的同一技能只展示一次。

稳定保留精灵和技能 ID；同名不等于同一身份。已有技能的首次赛季沿用最早记录，不会随着选择新赛季改变。

## S3 基线及来源边界

用户提供的飞书 S3 表 revision 610 已完整读取 553 个技能，规范化源文件为 `data/skill-query/s3-source.json`。重新导入命令：`node scripts/import-skill-query-source.mjs <完整的飞书读取结果.json>`；输入必须为包含完整 annotated_csv 的结果，不能截断。

该表与历史快照存在 292 条缺失关系，查询生成器只将其补入历史基线；带有 `meta.nrcSync.authoritativeLearnsets` 的当前快照直接使用新站全量学习表，不再追加历史关系。查询学习面包含不同进化形态，因此数量可能大于源表只列基础形态的数量。

当前学习表独立于 S3，删除或调整关系不会被旧补充表加回来。生成器遇到未知技能、精灵身份或重复赛季会直接报错。当前未实现移除关系展示。

技能详情使用所选赛季项目快照；S4 链接已切到新站。2026-09-10 已全量复核 622 个形态、579 个技能和 30,740 条学习关系，证据与重跑方法见 [新站同步说明](nrc-sync-2026-09-10.md)。查询不是实时访问 BWIKI，后续仍需要重新导入、测试、部署。
