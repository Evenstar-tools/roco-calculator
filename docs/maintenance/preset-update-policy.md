# 预设更新最小规则

2026-09-15，网页 2.0.2 同版本更新。

- 相同跳过；本地仍等于上次导入基准的旧配置直接更新；已修改或无法识别来源的配置保留；缺失配置新增。
- 旧用户没有基准时，与仓库历史预设逐项匹配，不凭更新时间推断是否手改。已存在基准时不再回退到历史匹配。
- 基准保存在本地配置的可选 presetBaseline 字段，普通保存沿用原基准；导出不携带此内部字段，旧 schema 仍兼容。
- 确认时重新读本地配置并计算更新项，避免覆盖预览后发生的手改。单技能手动设置原样保留。
- 按钮数量仅为更新与新增之和。无变化显示“已是最新”；仅剩手改项显示“手改配置已保留”。没有新增不代表无需更新。
- 历史来源为 public/data/presets/pvp-preset-history.json；之后更新推荐预设时运行 node scripts/build-preset-history.mjs 并提交结果。历史文件不可用时保留无基准项，不冒险覆盖。

验收：tests/state/preset-update.test.js 覆盖旧预设迁移、手改保留、基准优先、再次读取保护、新增和相同、基准持久化；tests/ui/config-library-dialog.test.jsx 覆盖新增为零但需要更新的按钮。
实际浏览器验证：97 条差异中 96 条旧预设更新，1 条手改保留；完成后相同 225、不同 1、新增 0，手动生命个体 17 未被改变。

本次不重新发布桌面安装包或上传微信开发版本。

## 后续更新与发布

1. **录入**：S5 推荐仍只维护 `data/presets/s5-popular-configs.json`，同步到 S5 源码分支与主发布分支；不另建一份普通版推荐。基础库与补充库避免同 ID 双重维护。新增精灵先确认种族值、身份与必要技能/特性支持；未知技能保持空位。两个首领暂用原种族值是本次明确决定，后续有确认资料再替换。
2. **保留历史**：预设修改提交后运行 `node scripts/build-preset-history.mjs`，把生成结果一并纳入发布；该脚本读取基础库和 S5 补充库的 Git 历史。正式切季时迁移同一身份，不丢旧配置识别基准；公告改动仍按各次补丁保存，不能用更新推荐替代平衡补丁审核。
3. **保护存档**：进入时仅对可新增/安全更新项显示约 2 秒提醒；检查失败、无变化或仅剩手改项保持静默。点击只打开预览，用户确认才应用；更新后再次进入不提醒。同版本配招更新也按内容差异处理，不依赖版本号变化。
4. **同步范围**：普通版继续只接入有配置的新精灵及必要依赖，旧精灵/技能/学习面不随 S5 公告改变；完整调整保留在 `/pre/`。先提交 S5 源码，再更新主发布分支 `config/preview-release.json` 的固定提交。国际服、桌面安装包、小程序按各自授权与数据兼容性发布，不把网页上线记作其他端已更新。
5. **验收**：定向检查配置性格/个体/技能、旧数据边界、速度/耐久候选；配置合并数量按实际唯一 ID 校验。上线回查旧库有更新、应用后无更新、手改保留三条链路。修复技能状态时覆盖实际受影响的单/四技能与攻/防入口，验证生效、解除及保留收益，不只看按钮文案。

发布构建须使用与线上一致的统计开关并通过原体积预算。提交、CI、云部署和公开网页回查分别确认；详见 [发布检查单](release-checklist.md)。
