## ① W15-04 设置说明收纳

1920×1080 显示设置：两段威力口径说明仍同时常驻。建议保留随当前模式变化的一句简述，完整原文放入原生折叠“口径说明”，默认收起，不增加页面。静态简述“技能自身规则调整后的威力，额外增益另算”；显示简述“结算本次增益并取整；手填值直接参与伤害计算”。保持上一轮的顶部关闭、Esc、焦点循环及即时保存。

临时 DOM 模拟测得设置窗高 711.34 → 668.16px，减少约 43px。截图为静态模式；实施后必须测试切换显示模式的简述、展开后原文完整、键盘操作和窄屏滚动。优先级 P3，属于信息收纳，不改计算口径。

## ② W15-05 选中结果行细边线

1920×1080 具体版四技能，武斗酷猫对迪莫。亮暗主题均已复核。建议当前行增加 3px 内侧主题色边线（亮紫 / 暗金），保留现有底纹、伤害红橙绿和字体，不增加“当前”标签，不改变行高。截图已分别注入并还原样式。实施后验证选择其他行时标记跟随、hover / focus 与明暗主题一致；移动结果抽屉不能产生额外位移。优先级 P3。

## ③ W15-06 极窄屏滚动条兼容

已定位：`src/styles/03-base-shell.css` 中 html 和 body 都有 `min-width: 320px`。桌面浏览器视口 320px，经典滚动条占 15px，可用 clientWidth 为 305px，但页面 scrollWidth 为 320px。临时取消根节点最小宽度后 scrollWidth 恢复 305px，定向探针未发现非 fixed 内容超出可用右边界。

只取消最小宽度会产生关联退化：赛季标题截断、武斗酷猫换成三字加一字。该发现归入本问题，不遗失。建议同步在 ≤360px 的紧凑布局压缩头部间距、图标按钮宽度至 32px，精灵头像 42→36px、头像与文字列间距 4px，使名称和赛季标题保留；不缩小正文字号，不改横屏。模拟结果：精灵信息可用文字列 63.5px，四字名称宽 60px，保持一行。

实施时要求根节点修复不靠 overflow hidden 掩盖；验证精简/具体、单/四技能、菜单/下拉、320/360/390px 与1920px，并检查更长名称不会被裁掉。测试应以真实可用宽度为准；当前证据不是手机真机复现。优先级 P2。
