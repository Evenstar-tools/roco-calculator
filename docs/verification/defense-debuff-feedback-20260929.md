# 水刃减四层物防反馈诊断

结论：减防后的物防提前四舍五入能够同时解释三组反馈。本地已修正负防御层数的内部精度，正式计算路径得到 438、418、350；面板仍显示整数。未提交、未推送。尚无完整对局配置和录像，不能将其扩大为所有能力变化的通用取整结论。

## 复现条件

- 产品版本：2.2.4；数据版本、规则版本均为 s4-2026-09-10；snapshotVersion：2。
- 60 级圣羽翼王，固执，物攻个体 60，攻击面板 246；水刃基础威力 115，对火属性倍率 2，单段，无额外天气、印记等。
- 防守方普通性格，生命个体 60；火神物防个体 0，音速犬分别物防个体 0 和 60，其余个体 0。为复现输入，不代表已核实实战配置；最后一例的物防投入仍属推测。
- 当前以 defenseLevelStage=-4 调用项目 CLI explain；对照实验取消层数输入，仅覆盖 defenderDefense=基础物防/1.4，避免该值再次被能力面板取整。对照未修改源码。

## 实现定位与范围

- src/domain/skill-result/numeric.js 的 abilityAdjustedStat：负四层使用基础物防 / 1.4。
- src/domain/skill-result/calculate-skill-result.js:805：将调整后的防御 Math.round 后传入伤害公式；这是本次定位的提前取整点。
- 同文件的 combatPanel 还承担整数展示；不应将展示取整和内部计算精度混为一谈。
- 现有测试包含正向强化后取整的预期；不能凭三个负物防样本删除全部攻防取整。
- 若把负四层改成直接乘 0.6，则三例得到 522、497、417，不符合反馈；本次证据不支持这种改法。
- 淘沙球对方物防 -40% 与新版 BWIKI 一致，产品契约逻辑映射为物理类别 -4 层。该说明确认减益来源，不证明游戏内部取整方式。

## 本地修复

- 新增共用的 defenseStatForDamage：总防御层数小于 0 时保留小数；零层及正向防御继续按原规则四舍五入，攻击计算不变。
- 普通技能与直接特性伤害复用此规则；物理、魔法按各自最终防御层数判断，不只对水刃或指定精灵做特例。
- combatPanel 的整数展示保持不变。后续按用户确认修正能力等级标签：主站和电鹿页显示“−4 层 · −40%”，鼠标悬停仅提示“原值的 71.4%”；只改展示，不影响伤害计算。沿用原布局与配色，已实看主站桌面/窄屏、电鹿窄屏，并操作加减确认数值及提示同步更新。
- 将三组反馈合并为 CLI 参数化回归，先确认旧代码失败，再修复通过；另覆盖直接特性伤害的同类问题。已有正向强化取整测试继续通过。
- 复算不再使用临时防御覆盖，而是恢复原始 defenseLevelStage=-4 输入，结果依次为 438、418、350；对应输入摘要仍为下表“当前”列，HP 占比和致命判断与上面的保留小数对照一致。
- 共享内核已同步到小程序，共享一致性检查和小程序计算回归通过。核心/CLI 回归、定向 ESLint 和差异格式检查通过；版本仍为 2.2.4，发布门禁和上线留到用户要求发布时执行。
- 保留工作区原有测试精简改动；仅在现存测试中加入本次回归，没有恢复其他已删除测试。
