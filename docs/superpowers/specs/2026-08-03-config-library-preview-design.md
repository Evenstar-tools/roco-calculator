# 配置库清单预览与导入统计收敛设计

## 目标

让用户在导出前确认具体包含哪些精灵和技能，并让导入预览优先回答“会新增什么、会覆盖什么”，不再用八个同权重数字增加理解成本。

## 导出清单

- “可导出 N 只精灵”区域可点击展开或收起。
- 展开后按现有导出顺序展示所有 `library.entries`。
- 每行展示精灵头像、精灵名称、性格和四个技能槽。
- 技能槽使用当前快照中的技能名称；空槽显示“空”。
- 清单设置最大高度并内部滚动，弹窗本身不随条目数无限拉长。
- 手动收藏、自动识别和跳过数量继续保留，展开状态不影响导出内容。
- 找不到当前快照名称时回退显示稳定 ID，不能因为展示失败阻止导出。

## 导入预览

首层仅固定展示三个会改变本机数据的核心数字：

- 新增配置
- 覆盖本机配置
- 新增收藏

其余校验结果收进“检查详情”：

- 缺失精灵
- 失效技能槽
- 未知特性字段
- 无效配置
- 文件内重复

当五项全部为零时，直接显示“检查通过，未发现兼容问题”，不渲染五个零值栏位。存在问题时，显示问题总数并允许展开；展开后只展示非零项。

## 名词定义

- “覆盖本机配置”：导入文件包含的精灵在本机已有个人配置，确认导入后会用文件配置覆盖本机配置。
- “文件内重复”：同一个导入文件中同一 `spiritId` 出现多次；解析时沿用现有规则，采用文件中最后一条有效配置。

两项可能同时发生，但不是同一统计口径。

## 交互与无障碍

- 展开按钮使用原生 `button`，包含 `aria-expanded` 和关联区域。
- 导出清单支持键盘展开、收起和滚动。
- 亮色、深色及窄窗口下不得横向溢出。
- 精灵头像加载失败不得造成布局跳动；固定头像尺寸并保留名称文本。

## 数据边界

- 不修改配置库 JSON 格式、导出筛选规则、导入合并规则或存储结构。
- 不修改收藏、自动识别、特性迁移和队伍数据。
- 本次只增加展示所需的快照名称映射与弹窗交互。

## 验收标准

- 导出弹窗可以展开查看每只精灵及其四个技能。
- 导出文件内容与改动前完全一致。
- 导入首屏只固定显示三个核心统计。
- 五个校验项全为零时显示检查通过；存在问题时只列出非零问题。
- “覆盖本机配置”和“文件内重复”有清晰、不同的说明。
- 单元、UI、端到端和生产构建回归通过。
