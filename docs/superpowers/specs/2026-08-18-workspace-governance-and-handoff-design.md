# 工作区治理与项目交接设计

## 目标

- 清理可重建缓存、重复构建产物和 `v1.5.5` 之前的旧安装包。
- 保留 `v1.5.5` 及之后的稳定安装包、当前桌面版、网页版和微信小程序开发内容。
- 不触碰任何含未提交改动的工作树，不通过清理动作改变 Git 历史或运行数据。
- 建立未来赛季数据并入、特殊规则适配、三端同步、测试和发布的固定流程。
- 形成通用维护文档与本机交接记录，后续接手者可以判断真实主线、当前风险和恢复路径。

## 清理边界

### 永久保留

- Git 仓库、所有分支、所有工作树及其未提交文件。
- `v1.5.5`、`v1.5.6`、`v1.5.7` 及之后版本的安装包、证书、校验文件和发布说明。
- 当前 Web、桌面端、微信小程序源码与运行数据。
- 当前赛季及历史赛季数据快照、精灵头像、技能与特性数据。
- 用户文档、设计规格、测试、发布脚本和 GitHub 首页素材。

### 直接清理

- `dist`、`output`、`test-results`、`playwright-report`、`.playwright-cli` 等可重建目录。
- 已确认重复且没有独立证据价值的临时安装包副本、上传回读缓存和构建日志。
- 临时打包目录中的 `.cache`、`win-unpacked.tmp` 等中间产物。

### 七天隔离

- `v1.5.5` 之前的安装包、证书和旧发布目录。
- 可能仍有追溯价值但不参与当前开发的录屏、截图和历史交付副本。
- 每个移动项记录原路径、隔离路径、大小、摘要和到期时间；七天内可以按清单原路恢复。

## 工作树保护

- 任何 `git status --porcelain` 非空的工作树都视为活跃开发内容。
- 清理脚本不得在工作树内执行 `git clean`、`reset`、`checkout`、递归删除或批量改名。
- 工作树整合应作为独立开发任务：先从 `origin/main` 建立新集成分支，再逐项迁移、测试和评审。
- 当前治理只记录工作树风险，不尝试替用户判断哪些未提交内容可以丢弃。

## 文档结构

- `docs/season-update-runbook.md`：赛季资料、数据快照和规则适配流程。
- `docs/maintenance/release-checklist.md`：提交、三端同步、测试、打包和发布门禁。
- `docs/maintenance/maintainer-handoff.md`：项目结构、版本关系、数据流和接手顺序。
- 本机交接记录：仅保存本机路径、工作树状态、隔离清单和恢复命令，不进入公开仓库。

## 验收

- 清理前后的 Git 工作树状态逐个一致。
- 保留版本安装包可定位，当前正式安装包摘要不变。
- Web、桌面和小程序源码、运行数据、头像和测试数量不减少。
- `acceptance:verify`、共享核心漂移检查、单元测试、Web 构建和小程序构建通过。
- 隔离清单可以准确恢复任意一个被移动文件。
