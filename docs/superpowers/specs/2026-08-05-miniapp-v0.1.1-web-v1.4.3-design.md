# 微信小程序 v0.1.1 对齐网页版 v1.4.3 设计

## 目标

将现有微信小程序从 `v0.1.0` 升级为 `v0.1.1`，在不重写竖屏界面的前提下，完整适配网页版 Git 标签 `v1.4.3` 已发布的确定性计算规则、必要交互、状态恢复和结果说明。

最终交付边界是：代码适配、生产构建、微信开发者工具成功导入、编译无报错和手机扫码真机预览。体验版上传、提交审核和正式发布由小程序管理员手动执行，不在本次自动操作范围内。

## 当前基线

- 网页发布基线：Git 标签 `v1.4.3`，产品版本 `1.4.3`。
- 小程序包版本：`0.1.0`。
- 小程序共享计算核心已通过 `npm run test:core-drift`，当前与网页源文件一致。
- `miniapp/project.config.json` 仍使用 `touristappid`；真实 AppID 和云环境参数不得写入公开提交。
- 主仓库同时存在独立的 `v1.4.4` 发布加固工作及未提交依赖调整。本次不得修改、提交或回退这些无关变更。

## 方案选择

采用“共享核心不分叉、补齐小程序适配层”的方案：

1. 网页 `src/domain`、`src/data` 和共享状态模块继续作为规则唯一来源。
2. `scripts/miniapp/sync-core.mjs` 负责生成小程序共享副本，`check-core-drift.mjs` 阻止漂移。
3. 小程序页面、组件、状态容器和展示层只实现微信端需要的交互适配，不复制第二套规则算法。
4. 不把网页 React DOM 组件直接搬入 Taro，也不进行无关界面重做。

## 功能适配范围

### v1.4.1 特性与状态

- 核对极光千兽家族、陨星虫、张弛有度、凡鹰、胡桃王子等特性条件是否能从小程序交互层完整输入。
- 支持硬门、守护之心、暖气及防御应对等确定性开关和结果说明。
- 确保双方视角、特性拥有者、持久化和分享恢复一致。

### v1.4.2 萌芽印记与技能

- 萌芽印记层数参与固定增益、放晴、点亮和暴风眼等确定性结算。
- 三连破按实际连击数累加能力等级。
- 配置库导入能展示无效配置的位置、原因和处理建议，并安全迁移兼容项。

### v1.4.3 动态威力与说明

- 闪击、鸣沙陷阱、魔能爆、冰锋横扫、怨力打击等动态威力使用共享计算结果。
- 单技能、四技能及结果区域统一展示简短计算过程。
- 固定威力技能不增加冗余说明；界面层不得再次推导或重复乘算。

## 版本与本地配置

- `miniapp/package.json` 和锁文件顶层版本升级为 `0.1.1`。
- 小程序界面或发布记录明确标注“小程序 v0.1.1，对齐网页核心 v1.4.3”。
- 网页产品版本保持 `1.4.3`，不得改成 `0.1.1`。
- 真实 AppID、云环境 ID、精确 manifest 文件 ID 和运行数据 SHA 仅写入被忽略的本地私有配置或进程环境变量。
- AppSecret 不进入前端、仓库、构建日志或交付证据。

## 数据流

1. 从网页已提交源读取共享规则和状态模块。
2. 同步脚本生成小程序共享目录并执行三层漂移校验。
3. 小程序状态容器收集 Taro 控件输入，调用共享计算核心。
4. 共享核心返回伤害、动态威力、命中数、特性过程和版本信息。
5. 小程序展示层只格式化结果，并将允许持久化的输入写入版本化本地存储。
6. 生产构建从真实云 manifest 加载运行数据；校验失败时显示可恢复错误，不输出伪计算结果。

## 错误与安全边界

- 缺少 AppID、云环境、manifest 文件 ID 或有效 SHA 时，生产验收必须失败并明确指出缺项。
- 云数据、缓存或分享载荷校验失败时，不使用未经校验的数据继续计算。
- 不新增微信登录、手机号、支付、广告、定位、通讯录、相册、摄像头或麦克风权限。
- 不把体验版上传、审核或发布写成已完成，除非管理员实际操作并提供后台证据。
