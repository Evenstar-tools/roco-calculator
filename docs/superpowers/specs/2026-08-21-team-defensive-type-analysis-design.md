# 队伍防守属性分析设计

## 结论

可以直接从现有六人队伍配置中分析整队防守弱点与抗性。第一版只读取每名成员的稳定精灵 ID 和当前数据快照中的属性，不使用性格、个体、技能威力或战斗临时状态。

计算必须复用 `src/domain/type-chart.js` 的最终倍率：双属性分别计算后相乘，并沿用当前项目的 ×3 上限与 ×0.25 下限。一只精灵面对一个进攻属性只统计一次，不能把两个防守属性拆开重复计数。

## 参考调研

- [Roco Showdown](https://rocopvp.tzrain.wiki/) 已提供队伍级阵容分析，用 18 属性统计队伍弱点，并扩展到防守承伤、携带技能打击面和 6×6 对位矩阵。
- [Roco Diviner 属性克制说明](https://roco.pet/guide/type-effectiveness/) 提供单只精灵的最终倍率口径：单属性 ×2／×1／×0.5；双属性相乘后，双重克制最高 ×3，双重抵抗最低 ×0.25。
- Roco Diviner 的精灵图鉴会把单只精灵的 ×3、×2、×0.5、×0.25 分组展示，可作为成员明细的表达参考。
- 公开页面中未检索到 lovepvp.top 的队伍级弱点统计，因此不以其作为本功能结构参考。

## 当前项目基础

- `TeamDrawer` 已持有当前队伍、六个成员和完整 `snapshot`。
- 队伍成员以具体形态 `spiritId` 保存，能够区分同族不同形态。
- `getTypeMultiplier()` 已支持快照属性矩阵、双属性相乘和倍率钳制。
- `analyzeDefensiveTypes()` 已用于结果栏的单只精灵“自身防御面”。
- 队伍存储结构无需升级；分析结果应在内存中派生，不写入本地存储。

## 范围

### 本轮实现

- 当前队伍按 18 个进攻属性逐项统计。
- 每个属性显示：弱点成员数、抗性成员数、普通承伤成员数。
- 弱点明细保留 ×3 与 ×2；抗性明细保留 ×0.5、×0.25，以及数据表未来可能出现的 ×0。
- 点击属性行展开具体成员、槽位、头像、名称和最终倍率。
- 支持“重点风险”和“全部属性”两种视图。
- 队伍未满六只时只统计已配置且数据有效的成员，并显示 `已配置 N/6`。
- 损坏或已失效成员不参与统计，并显示跳过数量。

### 本轮不实现

- 不统计成员技能的整队进攻覆盖。
- 不做双方队伍 6×6 对位矩阵。
- 不根据性格、个体、面板防御数值判断“硬不硬”。
- 不纳入天气、印记、临时减伤、能力等级或本回合状态。
- 不猜测条件特性带来的临时属性变化；队伍配置目前也没有完整战斗特性状态。

这些内容与“属性弱点”属于不同分析维度，后续需要时单独立项。

## 指标定义

对每个进攻属性 `attackType`，对每名有效成员计算：

```text
最终倍率 = getTypeMultiplier(attackType, 精灵属性列表, snapshot.typeChart)

最终倍率 > 1     → 弱点
最终倍率 = 1     → 普通
0 < 最终倍率 < 1 → 抗性
最终倍率 = 0     → 免疫（单列，但也计入非弱点）
```

排序不引入难以解释的综合分：

1. 弱点成员数多的在前。
2. 弱点数相同时，×3 成员数多的在前。
3. 再按抗性成员数少的在前。
4. 仍相同时沿用项目 18 属性固定顺序。

“重点风险”只显示至少有一名弱点成员的属性。“全部属性”显示 18 项，并允许查看纯抗性项。

## 界面方案

队伍抽屉左侧六人名单和顶部队伍工具栏保持不变。右侧顶部增加图标加短标签的紧凑分段按钮：

```text
[成员] [分析]
```

默认仍打开“成员”，不改变现有编辑流程。选择“分析”后，右侧只保留一条主线：防守面概览 → 属性摘要 → 按需展开成员。设计稿见 [team-defensive-type-analysis-mock.png](../../images/team-defensive-type-analysis-mock.png)。

```text
🛡 防守面  6/6                         [重点] [全部]
💔 弱   🛡 抗

[电图标] 电   💔 2   🛡 1   [×3·1] [×2·1]       ⌃
             💔  4 圣水守护 ×2   5 彩蝶鲨 ×3
             🛡  1 伊兰亚龙 ×0.5
[草图标] 草   💔 2   🛡 2   [×2·2] [×0.5·1] [×0.25·1]  ⌄
```

### 可见文案

常驻文案只允许出现：`成员`、`分析`、`防守面`、`6/6`、`重点`、`全部`、`弱`、`抗`、属性名、成员名和倍率。禁止再显示“队伍防守属性分析”“弱点成员数”“抗性成员数”“普通承伤”“净暴露”等长标签或解释性分数。

- “弱／抗”只在顶部图例出现一次；每行用破盾和盾牌图标复用含义。
- `6/6` 表示有效成员数；无须再写“已配置”。
- `重点` 只显示存在弱点成员的属性；`全部` 显示 18 属性。
- 中性成员数只用于内部数量守恒，不在默认界面显示。
- 失效成员使用警告图标和 Tooltip `跳过 N 个失效成员`，不占一整行说明。
- 空状态只显示属性图标轮廓和 `添加精灵后查看`。

### 图标规则

- 属性使用现有 `ElementIcon` 与本地官方属性素材，不用 Emoji 或文本圆点代替。
- “弱”使用 Phosphor 破盾／警示类图标；“抗”使用盾牌勾选图标；展开使用 `CaretDown`。
- `成员` 使用成员／身份图标，`分析` 使用柱状图或极坐标图标。
- 只有含义唯一的操作可纯图标化；所有纯图标按钮必须有 `aria-label`、`title` 或现有 Tooltip。
- 不用颜色作为唯一信号：图标形状、数字和倍率必须同时存在。

### 密度与视觉层级

- 右侧内容使用一个连续列表，不给每个属性再套独立卡片。
- 摘要行桌面高度 44px；属性图标 28px；成员头像 28px；点击区域不低于 36px。
- 使用 8px 行内间距、12px 组间距、16px 面板内边距；列表用 1px 分隔线组织。
- 弱点为浅红底、红色数字；抗性为浅绿底、绿色数字；紫色仅用于选中页签、焦点和主操作。
- 倍率分布显示可解释的 `×3·1`、`×2·1`、`×0.5·1`，不得生成平均倍率、净暴露分或综合评分。
- 只展开当前点击的属性；展开区按“弱／抗”分为两列，展示槽位、头像、名称和最终倍率。
- 不使用渐变、装饰性阴影、大面积底色、嵌套卡片或大矩阵。

### 响应式与无障碍

- 桌面保持左侧 320px 阵容、右侧自适应分析区；1024px 下不压缩成员名与倍率。
- 低于 900px 时不再左右并排：队伍名单和分析作为同一抽屉内两个一级页签，分析占满宽度。
- 390px 移动端摘要行改为两行：首行属性、弱数、抗数；次行倍率分布；点击区域不低于 44px。
- 深色模式降低红绿底色饱和度并提高文字、边框和焦点环对比度；倍率数字必须达到正文可读对比度。
- 属性摘要按钮的无障碍名称必须完整，例如：`电，弱点 2，只，抗性 1，只，展开成员明细`。

## 示例队伍验算

以截图中的六只精灵为例：伊兰亚龙、飞飞钥、友爱星飞、圣水守护、彩蝶鲨、白金独角兽。按当前 S3 数据与现有属性引擎：

- 电：弱 2（圣水守护 ×2、彩蝶鲨 ×3），抗 1（伊兰亚龙 ×0.5）。
- 草：弱 2（圣水守护、白金独角兽均 ×2），抗 2（伊兰亚龙 ×0.5、飞飞钥 ×0.25）。
- 冰：弱 2（伊兰亚龙、彩蝶鲨均 ×2），抗 1（飞飞钥 ×0.5）。
- 火：弱 1（飞飞钥 ×3），抗 3（伊兰亚龙、圣水守护、彩蝶鲨均 ×0.5）。

这组结果作为实现后的固定验收样例，防止统计口径漂移。

## 交互与状态

- 分析随成员新增、删除、换形态立即重算，不需要“开始分析”按钮。
- 切换队伍时保持当前页签；若新队伍为空，显示空状态而不是旧结果。
- 展开状态按属性名保存于组件局部状态；切换队伍时全部收起。
- 分析功能不增加全局设置，不影响主界面的“属性分析”开关。
- 分析结果不进入分享链接、配置库或队伍存储，避免产生版本迁移。

## 验收标准

- 六人完整队伍可得到 18 属性的弱点、抗性和普通承伤计数。
- 每个属性的三类数量之和等于有效成员数；免疫单列时不重复计入抗性。
- 双属性精灵在每个进攻属性下只出现一次。
- ×3、×2、×0.5、×0.25 明细与单只精灵属性分析一致。
- 空位、失效精灵和具体形态均被正确处理。
- 修改任一成员后无需关闭抽屉即可看到新结果。
- 桌面、窄窗口、移动端和深色模式无溢出、错位或低对比度文本。
- 不修改队伍 schema、伤害公式和主界面属性分析结果。
