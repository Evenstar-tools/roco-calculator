# v1.4.4 发布收口设计

## 目标

把 v1.4.3 后的仓库状态收口为可重复验证、可离线使用、可发布和可维护的 v1.4.4。此次不新增计算功能，不升级前端框架大版本，不改变伤害公式、状态结构或用户数据格式。

## 范围

1. 消除当前单元测试中的 React 异步告警，确保测试结束前所有懒加载更新均已完成。
2. 调整依赖分类并修复可安全升级的依赖漏洞；生产依赖审计必须为零高危，开发工具链剩余风险必须有证据说明且不得进入桌面包。
3. 将浏览器端到端测试切到生产构建，补 Service Worker 真离线回退验证。
4. 建立真实产物体积预算和冷启动、热启动、技能检索耗时阈值。
5. 用现有规则与状态生命周期测试补足当前快照的收口证据，不把“未来数据可能新增规则”误记为当前缺陷。
6. 更新验收矩阵、版本号、缓存名和变更记录。
7. 旧安装包和过期分支先进入七天可恢复隔离区，再清理工作区生成物；不直接永久删除。
8. 完整回归后发布 v1.4.4，验证 GitHub CI、Release、安装包品牌与本机安装。

## 实现原则

- 测试先行：每个行为修复先建立失败信号，再实现最小改动。
- 生产测试：E2E 使用 `vite preview` 提供生产构建，避免开发服务器绕过 Service Worker。
- 预算可解释：阈值以当前实测值加合理余量制定，既能阻止明显回退，也不因资源图片的正常增长频繁误报。
- 依赖不冒进：只做补丁或同主版本升级；不升级 Vite、Vitest、Playwright 等大版本。
- 清理可恢复：旧安装包、旧分支先留存校验和与 Git bundle，七天后才允许永久删除。

## 验收标准

- `npm audit --omit=dev` 无高危；完整审计无可修复高危，或开发链剩余项有明确不随包分发的证据。
- 单元测试无 React `act` 告警。
- 生产 E2E 可在浏览器断网后重载并继续读取应用壳和运行时数据。
- 构建产物通过体积预算，生产 E2E 通过冷启动、热启动和技能检索阈值。
- 当前快照的动态技能、特性和状态生命周期证据在验收矩阵中为“通过”。
- 全量命令、桌面品牌扫描、CI、Release 校验和、本机安装与启动均通过。
- 工作区只保留最新版交付物；旧包和旧分支备份位于七天隔离区并附清单。
