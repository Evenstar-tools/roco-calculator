# 静态威力与面板威力口径设计

## 目标

将当前容易混淆的“实际威力 / 面板威力 / 自动”收敛为两种用户可理解的口径：

- `静态威力`：默认口径，接近 v1.5.5 技能栏的简洁使用方式，但重新划清计算边界。
- `面板威力`：技能经过全部威力相关结算后，在游戏界面显示并进入伤害公式的整数威力。

本设计只重排威力阶段和输入语义，不修改既有技能、特性、印记、天气、属性克制、能力等级、连击和伤害规则。

## 口径定义

### 静态威力

自动静态威力包含：

1. 技能库基础威力。
2. 技能自身动态规则，例如速度差、攻防差、当前生命、能量、栏位、使用次数和条件分支。
3. 技能自身声明的威力百分比规则。
4. 已应用到技能上的固定威力增减，例如羽化加速、漫反射和按栏位生效的固定威力。

自动静态威力不包含：

- 精灵特性、血脉、契约和印记带来的固定威力或百分比威力。
- 状态、特性和印记形成的外部百分比威力区。
- 本系、属性克制、天气、攻防能力等级和其他威力乘区。
- 攻防面板、减伤、最终伤害倍率和连击伤害。

技能栏只显示整数静态威力。自动计算内部仍保留既有精度，避免仅因显示方式变化而改变未手动覆盖时的伤害。

### 面板威力

面板威力是完整威力链结算后的整数：

```text
静态威力
+ 特性 / 血脉 / 契约 / 印记固定威力
× 技能自身之外的威力百分比加算区
× 本系
× 属性克制
× 天气
× 攻防能力等级
× 其他威力乘区
= 面板威力（四舍五入为整数）
```

面板威力之后才进入攻防数值、减伤、最终倍率和连击伤害结算。

## 手动输入语义

采用方案 A。

### 手动静态威力

- 用户输入的是“固定威力调整完成后的静态威力”。
- 输入后替换技能自身规则、技能自身百分比和固定威力增减的自动结果。
- 羽化加速等固定威力不得再次叠加。
- 特性、印记、本系、克制、天气和能力等级等静态层之后的规则仍正常结算。
- 点击恢复按钮后删除覆盖，重新跟随全部自动状态。

### 手动面板威力

- 用户输入的是最终面板威力。
- 输入后不再重复计算特性、印记、本系、克制、天气、能力等级和其他威力乘区。
- 该整数直接进入伤害公式。

两种手动输入均限制为 `0–9999` 的整数。非法输入不提交，不静默截断。

## 界面规则

- 显示设置改为 `静态威力 / 面板威力`。
- 首次安装和没有有效旧设置时默认 `静态威力`。
- 删除用户可见的“实际威力”。
- 删除技能行常驻的“自动”文字；未手动覆盖就是普通显示状态。
- 手动覆盖后显示紧凑的恢复图标，Tooltip 和无障碍名称为“恢复自动威力”。
- 单技能和四技能共享相同的口径、输入组件和恢复逻辑。
- 动态技能的小字继续解释来源，例如“速度差 111 → 静态威力 190”。
- 伤害计算过程使用“静态威力 → 外部威力结算 → 面板威力 → 伤害”的顺序。

## 兼容与迁移

- 旧显示设置 `actual` 读取为 `static`；旧 `panel` 保持 `panel`。
- 写入新设置时只保存 `static` 或 `panel`。
- 旧 `actual` 手动覆盖按最接近的语义迁移为手动静态威力，保留用户数值。
- 旧 `panel` 手动覆盖保持面板威力。
- 旧 `legacy-base` 继续通过兼容入口读取，不改变旧分享链接和精灵记忆。
- 显示设置仍不写入分享链接、队伍或配置库。

## 验收标准

1. 首次安装默认显示静态威力。
2. 自动静态威力不因特性、印记、克制、天气或能力等级变化而改变。
3. 羽化加速等固定威力生效后，自动静态威力随之变化。
4. 手动静态威力后再触发羽化加速，输入值和对应伤害不重复增加固定威力。
5. 恢复自动后，静态威力立即读取当前状态并重新计算。
6. 面板威力包含完整威力结算且只显示整数。
7. 手动面板威力不重复应用任何威力乘区。
8. 切换显示口径本身不改变未手动覆盖的伤害。
9. 单技能、四技能、双方技能栏和伤害公式使用同一语义。
10. 旧分享、旧精灵记忆和旧显示偏好可读取。
