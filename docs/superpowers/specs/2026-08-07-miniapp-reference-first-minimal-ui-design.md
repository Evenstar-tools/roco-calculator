# 微信小程序参考图导向的极简界面设计

日期：2026-08-07  
版本：小程序 v0.1.1，网页核心 v1.4.3  
状态：已确认，采用方案 A

## 1. 目标

以用户提供的“闪耀大赛”手机截图为排版参考，重做洛克对战计算器的小程序工作台。目标不是逐像素复制另一个产品，而是复用其清晰的操作顺序：双方对象同屏、参数成组、技能与结果合并、次要条件收拢。

用户应能在主屏上快速完成：

1. 更换攻击方或防守方精灵。
2. 查看双方最终六维，并进入性格与个体编辑。
3. 切换单技能或四技能，选择技能并直接查看伤害。
4. 调整目标当前生命和必要战斗条件。
5. 按需查看完整结算，而不是先阅读大段说明。

## 2. 视觉原则

- 一屏只表达一条计算路径，不堆叠同权重卡片。
- 使用暖灰页面底色、白色平面容器和克制边框，不使用紫色主题、玻璃效果或装饰性渐变。
- 攻击方使用淡黄与琥珀色，防守方使用淡蓝与蓝色，伤害结果使用珊瑚红，正向修正使用低饱和绿色。
- 圆角统一为 10–12 px；阴影只用于浮层和必要层级，主页面依靠留白与分隔线组织。
- 中文正文不小于 14 px，辅助信息不小于 12 px；系统字体优先，不引入外部字体。
- 精灵头像、属性图标和六维图标均使用现有真实资源，不生成虚构素材，不使用 Emoji 代替图标。

建议色值：

- 页面背景：`#F6F3E9`
- 主表面：`#FFFFFF`
- 主文字：`#20242B`
- 次文字：`#747A82`
- 分隔线：`#E5E1D7`
- 攻击强调：`#C9912E`，浅底 `#FFF4D6`
- 防守强调：`#4C88C7`，浅底 `#EAF4FF`
- 结果强调：`#E35B57`
- 正向数值：`#4E965D`

## 3. 手机竖屏布局

### 3.1 顶栏

仅保留“洛克对战计算器”、配置数量和更多入口。配置和更多使用低权重文字按钮，不占据主视觉。参考图中的“属性计算 / 伤害计算”页签不适用于当前产品，不照搬。

### 3.2 对战对象

- 攻击方和防守方精灵卡左右并排，中间放置交换攻守图标。
- 卡片展示：真实头像、侧别、精灵名、属性图标。
- 点击整张精灵卡立即打开该侧精灵搜索，不保留独立“更换”按钮。
- 当前计算方向通过顶部细色条、浅色背景和交换图标方向共同表达，不只依赖文字颜色。
- 精灵选择完成后自动关闭搜索并返回原滚动位置；点击遮罩、系统返回或其他主控件也能关闭。

### 3.3 双方六维参数

- 双方各使用 2×3 六维网格，与上方精灵卡严格对齐。
- 每格展示能力名称和最终面板数值；受性格影响的提升或降低使用绿色上箭头或红色下箭头。
- 六格均为同一个“参数设置”触控入口。点击任意格打开该侧参数面板，不在主屏继续铺开性格与个体两行图标。
- 参数面板保留现有快速性格和个体能力：先显示当前性格摘要与六项个体快捷开关，再提供完整数值编辑。
- 修改后六维网格立即刷新，面板可通过选择完成、完成按钮、遮罩和系统返回关闭。

### 3.4 技能与结果

- 单技能 / 四技能分段控件放在技能列表顶部，与技能列表组成一个容器。
- 手机主屏只展示当前计算方向的进攻侧技能，不同时铺开双方技能面板。
- 每条技能行展示：属性图标、技能名、类型、威力、能量，以及右侧伤害和 HP 百分比。
- 没有技能专属插画时，用真实属性图标放入固定 40 px 图标容器，不生成伪造技能图片。
- 点击技能行主体打开技能搜索；选择完成后关闭并保留该行选中态。
- 点击右侧结果区域切换当前技能并打开结果详情，必须阻止事件冒泡，不能同时打开技能搜索。
- 选中技能使用左侧色条和浅底；按下状态使用轻微背景加深与 `0.98` 缩放，松手恢复。
- 单技能模式只显示一行；四技能模式固定显示四行，不使用超长横向拉条。

### 3.5 条件与目标生命

- 技能列表下方保留一条条件摘要，直接显示“目标 HP”紧凑输入和非默认条件数量。
- 天气、减伤、倍率、特性、印记等默认不铺开；点击摘要进入底部条件面板。
- 当前技能必需的手动威力、连击数或动态选择紧贴选中技能行显示，避免用户去条件面板寻找必填项。
- 条件面板继续覆盖现有全部变量，按“常用、特性、印记、高级”分组。

### 3.6 结果详情

结果详情使用底部面板，顺序固定为：

1. 当前技能伤害、HP 百分比、剩余生命。
2. 四技能紧凑对比。
3. 已生效条件摘要。
4. 计算提醒。
5. 默认折叠的公式和结算明细。

主页面不再显示独立的大结果卡；技能行右侧结果就是主反馈。

## 4. iPad 布局

- 1024×768 横屏继续采用三栏工作台：攻击方、 防守方、右侧结果栏。
- 820×1180 竖屏采用双列参数与技能区，结果放在下方完整宽度区域，不放大手机固定结果条。
- 双方精灵、六维网格和技能行与手机版共用组件和视觉语法。
- iPad 结果栏继续显示当前技能主结果和四技能对比，但公式默认折叠。
- 条件编辑使用右侧抽屉或居中面板，打开时保留对战上下文，不跳转到独立长页面。

## 5. 交互状态与数据流

- 计算、记忆、收藏配置、分享协议和持久化状态保持不变。
- `BattleWorkspace` 只新增一个展示层状态，记录当前编辑侧、当前技能格和当前打开的面板。
- 同一时刻只允许一个面板打开：精灵、参数、技能、条件、结果、配置库或更多。
- 打开新面板必须原子关闭旧面板；所有面板统一支持遮罩、完成、选择成功、系统返回和页面隐藏关闭。
- 组件通过现有 store action 修改业务数据，不复制另一份表单状态。
- 数据缺失时显示可恢复提示：缺精灵时提示选择精灵，缺技能时显示“请选择技能”，无法精确计算时保留技能行并说明需要的输入，不能白屏。

## 6. 保留范围

以下能力必须完整保留：

- 592 个精灵及真实头像。
- 属性小图标与六维图标。
- 单技能、四技能和攻守交换。
- 性格、个体、手动威力、连击、目标当前生命。
- 天气、减伤、倍率、双方特性与动态字段、正负印记。
- 记忆系统、收藏配置、主动导入常用精灵配置、分享与本地持久化。
- 小程序 v0.1.1 与网页核心 v1.4.3 的版本协议。

## 7. 工程边界

- 不重写计算核心、持久化协议或收藏配置格式。
- 不新增图片资源；复用现有精灵、属性和六维素材，控制主包体积。
- 不继续在 5,850 行页面样式末尾追加大段互相覆盖的补丁。新布局规则按基础、对战、参数、技能、条件、结果和响应式分区，并移除被替代规则。
- 生产包继续以 2 MiB 为硬上限；若界面代码增加导致超限，使用确定性 JS/CSS 压缩，不删除功能或精灵数据换体积。

## 8. 验收标准

### 功能与交互

- 用户从默认页完成更换双方精灵、修改一项参数、切换四技能、更换一个技能、调整目标 HP、设置一个条件并查看详情，每一步最多一次进入对应面板。
- 所有主要触控目标不小于 44×44 px，并有默认、按下、选中或展开状态。
- 精灵、参数、技能搜索和所有底部面板均可稳定关闭；关闭后不跳页、不丢滚动位置。
- 技能行主体与结果区域执行不同动作，不发生串点。

### 视觉

- 320×844、375×812、390×844、430×932 无横向溢出、中文竖排、文字重叠、头像或图标裁剪、缩放错位和无效大空白。
- 820×1180 与 1024×768 保持双列或三栏效率，不出现手机版模块被简单放大的效果。
- 首屏 3 秒内能识别双方精灵、双方六维、当前模式和技能伤害入口。
- `design-qa.md` 对照参考图和最终截图，P0/P1/P2 全部关闭，最终结果为 `passed`。

### 自动验证与交付

- 为六维参数入口、技能行双动作、面板互斥关闭、手机/iPad响应式布局新增回归测试。
- 小程序全量测试、共享核心漂移检查、微信生产构建和发布门禁全部通过。
- 主包不超过 2 MiB。
- 使用微信开发者工具完成编译，并对手机与 iPad 关键页面做视觉回读后交付。
