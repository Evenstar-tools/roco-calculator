# 工作区治理与项目交接实施计划

> 本计划只处理开发环境治理和文档，不修改伤害公式、数据内容或界面功能。

## 任务一：建立清理基线

1. 记录仓库、分支、工作树、版本和 Git 状态。
2. 统计安装包、发布目录、缓存、构建产物和依赖目录大小。
3. 生成保留清单：`v1.5.5` 及之后版本、当前三端源码和正式交付物。
4. 运行 `npm run acceptance:verify`、`npm run test:core-drift` 和 `npm test`。

验收：基线结果、文件数量和工作树状态写入本机交接记录。

## 任务二：执行可恢复清理

1. 创建日期化隔离目录与 JSON 清单。
2. 将 `v1.5.5` 之前的安装包和独立旧交付物移入隔离区。
3. 直接清理可以由现有脚本重新生成的缓存和构建产物。
4. 不清理任何脏工作树内的未跟踪文件，不移除 `node_modules`，避免中断开发。
5. 重新统计空间并校验隔离清单。

验收：每个隔离项包含原路径、目标路径、大小和 SHA256；直接清理项仅来自明确可重建目录。

## 任务三：补齐维护与交接文档

1. 扩展赛季更新流程，覆盖来源登记、差异审查、特殊规则、素材和三端同步。
2. 新增提交与发布检查单，明确 Web、桌面端、小程序的独立门禁。
3. 新增维护者交接文档，说明架构、数据源、状态存储、发布物和故障恢复。
4. 创建本机交接记录，记录当前分支/工作树风险和隔离区恢复方法。

验收：文档不包含令牌、账号或用户私有配置；命令与 `package.json` 保持一致。

## 任务四：清理后回归

依次执行：

```text
npm run data:validate
npm run acceptance:verify
npm run test:core-drift
npm test
npm run build
npm run miniapp:test
npm run miniapp:build
git diff --check
```

验收：清理前后 Git 状态一致；三个客户端的源码和构建入口完整；当前安装包摘要不变。

## 任务五：后续版本治理

- 每次赛季更新建立独立分支和数据差异报告。
- 每条技能/特性规则必须有来源、规则分类、测试向量和回退点。
- 共享核心先在 Web 源码完成并测试，再通过同步脚本进入小程序。
- 每次发布同步更新版本号、用户更新日志、完整 CHANGELOG、安装包校验和 GitHub Release。
- 发布完成后仅保留当前稳定版和上一稳定版的本机构建产物；更早版本由 GitHub Release 长期保存。
